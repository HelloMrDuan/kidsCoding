# V2 视觉与布局冻结规则

V2 是当前唯一已批准的全站视觉设计基线。项目负责人于 2026-10-11 确认冻结；设计归档 [PR #33](https://github.com/HelloMrDuan/kidsCoding/pull/33)，合并提交 `2ab0687a908af41891794aa45d83d41fea7b434a`。

## 实施依据与优先级

所有后续 UI PR 必须对照完整的 [prototype.html](./prototype.html) 和 [离线交互原型](./KidsCoding-V2-Interactive.html)。两者除图片存储方式外相同；[README](./README.md) 和 [DESIGN-SPEC](./DESIGN-SPEC.md) 为补充规范。旧 V1 原型、旧 CSS、roadmap 中旧颜色或布局数值不能覆盖 V2。没有单独页面稿的界面沿用同一设计系统。

## 冻结范围

- 侧边栏、顶部导航、内容区域及分栏位置与顺序；桌面 222px 导航、76px 顶栏及原型的 1180/860/600px 响应式规则。
- 海军蓝导航、科技蓝主操作、中性浅色内容区；字体层级、间距、按钮尺寸、圆角、边界、阴影、图标与素材风格。
- 编辑区与舞台比例，工具栏、标签、课程步骤、运行/重置、保存入口和反馈位置；手机按原型分区切换，禁止压缩桌面三栏。

未经项目负责人明确批准，任何 AI、开发者或后续 Codex 会话均不得改变上述布局、颜色体系或组件视觉，也不得以优化、重构、开发方便或缺少素材为由重新设计 V2、定义 V3、添加大 Banner、浮层模块或替换美术风格。

## 业务接入与变更流程

允许绑定真实数据、真实按钮动作、必要的加载/错误/空状态/权限状态和实现同一布局所需的技术细节。未定义的响应式细节须延续 V2；不得冒用原型中的演示进度、作品或运行结果。素材正式使用前必须核实权利。

遇到业务与冻结布局冲突，或两个设计文件的具体要求无法确定，先记录冲突位置、截图及最小修改方案，等待项目负责人裁定，禁止先改后报。任何设计变更必须先获得明确批准，再单独走设计变更 PR 和验收，并记录批准内容与范围。

## 每项 UI 任务的验收

实际代码 → 正反/恢复测试 → 真 Chrome Playwright 1440×900、768×1024、375×812 对比截图 → 单任务 PR → 全部 CI 成功且无阻塞 → 合并 → main CI → 台账与日志。视觉和功能独立验收；未经批准的布局差异即使测试通过也不能作为页面验收成功。动态内容或设备差异须逐项附图说明，不产生新的设计基准。

UX-001 只落实冻结规则和视觉基础 tokens；各页面布局依原任务队列逐步实施，不得因基础样式或文档完成宣称十页迁移完成。本规则适用于所有未来 PR 和 Codex 新会话，阅读旧开发规范时也必须先遵守此文件。

## 已裁定的对比度冲突

2026-10-11 项目负责人明确选择：**严格保持原型文字颜色，记录 AA 缺口**。因此不得擅自加深次级正文或状态文字。白底小字号的次级/成功/警告/错误色实测约 4.18/4.48/4.28/4.20，低于 4.5；原型浅蓝焦点环对白底也低于非文本 3。保留色值不等于 AA 合格。UX-001 的全 AA 验收条件尚未满足，不能伪报 completed；需负责人后续明确调整验收或批准设计变更才能关闭该缺口。

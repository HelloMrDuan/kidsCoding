# Golden Lessons · G0 Blockly 网格课堂样板

样板课程为 `G0-U3-L05`《用循环画围栏》。孩子先观察三条边留下的缺口，补齐围栏，再分别练习转角连接、循环控制和朝向调试。最后选择两格或三格边长，制作可回放的本机作品。

## 从课程契约接入

1. 在 `apps/web/src/content/curriculum/` 新建以课程知识点命名的定义文件。使用 `g0-u1-grid-lessons.ts` 的 `GridLesson`，参考 `g0-u3-fence-lesson.ts`。写明目标、情境、讲解、预置积木和三个提示层次。分别为故障观察、引导、两种不同练习及开放作品提供至少一个能通过的程序和一个会失败的程序。
2. 在相应网格课程注册表登记课程。已有的 `/learn/grid-lab/[lessonId]`、目录详情与成熟度会共用这一注册表。确需新的课程组时，把同一个注册表接到路由、`lesson-maturity.ts` 和 `lesson-schema-snapshot.ts`。
3. 用 `GridLevel` 描述地图、起点朝向及可观察的判定条件。围栏的 `route` 包含起点和每个相邻格，闭合路径可沿两个方向通过，`goalFacing` 检查结束朝向。`GridStage` 用同一地图显示目标，再按运行帧画出孩子实际经过的路线。地图或角色变化先用已登记的授权素材。
4. 在课程设置 `layoutMode: 'golden'` 后，`GridLab` 使用 `GoldenLessonLayout` 的任务、编辑器、舞台和运行插槽。其他课程沿用原课堂壳。编辑器传入 `BlocklyWorkspace layoutMode="golden"`，保留原生 Toolbox、Flyout、Zelos、撤销、缩放和垃圾桶。点按添加放在辅助抽屉内。平板舞台在上，手机切换面板只改变可见性。桌面折叠教学、全屏和改尺寸都沿用同一个 Blockly 实例。
5. 调用 `runGridProgram(level, blocks)`，依据轨迹、位置、朝向及本课的单层重复要求判定。用正反绕行、少一边、漏转向、平铺及双层嵌套覆盖正反测试。围栏练习要求一层重复，嵌套循环留到 M0/G1。
6. 围栏课堂和作品中心共用 `kids-lesson-owner-v1:<编码后的身份>:kids-grid-lesson-v1:<课程 ID>`。账号使用服务端确认的 Supabase 用户 ID，游客使用现有游客 ID；未分配 ID 时使用该浏览器的游客区。账号、游客区和课节各自保留草稿与本机成就，浏览器切换身份后重新确认会话。存储失败时保留当前编辑，可在页面重试。云同步、正式成绩和 RLS 由正式发布流程管理。

### 旧围栏草稿迁移

历史的 `kids-grid-lesson-v1:G0-U3-L05` 没有可确认的作者身份，保留原键作备份。课堂和作品中心的读写、删除均只作用于当前身份。共享设备上由教师或监护人先核实原作者，仅在确认归属后从备份提取所需关卡的积木数组，按 `{ "schema": 1, "lessonId": "G0-U3-L05", "stepId": "该关 ID", "blocks": [...] }` 保存为 JSON。以原作者身份打开同一关，使用“积木文件 → 导入积木”，再运行及保存。第 3 关保留文件用 ID `nested-square`，界面只教一层重复。历史通关、反思和成就需重新取得。实体共享设备和带 RLS 的同步仍需预发布验收。

## 到其他路线的复用范围

G0 的网格、方向、路径、循环类课程可复用执行器与舞台；事件课选用同仓库的 `EventLab`。G1 可共用 Blockly 编辑、指引与草稿设计，故事场景、角色事件与对白时序需要故事引擎和独立判定。G2/G3 复用教学契约、正反测试方法和证据格式，编辑、资产、运行与完整作品保存使用 Scratch GUI、Scratch VM 和 `.sb3`。本样板的正方形轨迹、教学内容及题目答案只适用于本课。

## 素材与回滚

- 舞台采用仓库内已有的小狐狸原创矢量、网格和图形组件。围栏轨迹由执行器的格子坐标生成，无外部图片或音效。指令播报使用浏览器语音合成功能。
- 设计包的旧界面、目标图和响应式图仅作为对照证据。工作区由 React、CSS、真实 Blockly 和运行帧渲染。
- 取消课程的 `layoutMode` 即可恢复现有网格课堂壳，草稿键和程序格式兼容。回滚课程目录注册时保留本机作品，重新放开后可读取。

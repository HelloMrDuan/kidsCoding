# 课程内容契约（Lesson Content Contract）

版本：`p0-kitten-workspace-v1.1`
地位：工作区外壳只渲染契约内容，不编造课程内容。课节切换不得只换标题：标题、目标、任务、提示、结果、总结六方全部来自本课契约。

## 一、契约字段

| 字段 | 说明 |
|---|---|
| `lessonId` | 课节 ID，如 `G2-U3-L02`、`A1-U3-L02`；与台账课节 ID 一致 |
| `title` | 课节标题 |
| `goal5` | 首屏五要素，恰 5 条：今天学什么 / 要解决什么问题 / 学完能做什么 / 和上节课的联系 / 当前要完成哪一步；一主要目标，其他只作前置或辅助 |
| `brief` | 任务简报（一两句目标 + 当前步骤） |
| `step` | 当前步骤文案 |
| `hints[3]` | 三级提示：1 级方向、2 级知识点 / 积木、3 级局部示范与调试线索；完整参考实现只在事后节点出现 |
| `engine` | 引擎类型：`scratch-vm` / `blockly` / `summary`（摘要编辑，非积木）/ `slot`（通用插槽课，见下） |
| `judging` | 判定规则（见第三节）：舞台结果、任务判定、知识证据三层 |
| `draftKey` | 草稿键，格式 `kidscoding-draft:{lessonId}`，按课节分键 |
| `scopeLabel` | 任务类型诚实标注：`教学定向` 或 `开放创作`；行为化评测不支持时只能标教学定向并写明缺口 |

`slot`（OPS-026，Issue #482 首席裁定方案②）：通用插槽课引擎。课程自带 EditorSlot，不强制挂载 Blockly/Scratch；无真实运行目标时不显示运行按钮，不虚构运行结果；判定由插槽自有检查产生，插槽可向外壳上报判定（上报通道待 #488 合并后接入，在此之前不上报），不上报时反馈区只显示中性占位文案。`json` 不是引擎值：JSON 课程用 `slot`，不得冒用 `summary`；`summary` 仍只表示摘要编辑。

## 二、渲染规则

- 外壳从契约读取并渲染目标栏、任务简报、抽屉、提示、反馈占位；不得在外壳或切换逻辑里硬编码课程标题、任务文案或答案。
- 切换课节时：先保存当前课草稿（分键），再载入目标课草稿；选句、事实核对、提示、草稿、反馈全部绑定本课节，不得跨课残留。
- 保存失败必须显示“未能保存”，不得显示“已保存”（fail-closed）。

## 三、判定规则（三层分离）

一次运行必须同时输出三层，UI 三行分别呈现，不得混为一谈：

1. **舞台结果**：舞台真实状态（坐标、碰撞与否、差值、阈值）。
2. **任务判定**：学生是否完成本节任务（须真实移动并达成行为目标；只发生碰撞、参数错误、未达目标均为未完成）。
3. **知识证据**：本节核心知识点是否被真实使用并产生效果（例如循环确实移动了角色；未用指定知识点即使达成行为目标也不得写“已掌握”）。

“已掌握”“已完成”只在任务与知识证据同时通过时出现。判定按行为目标（真实运行结果）进行，不按积木排列与标准答案逐块比对。

## 四、示例契约值（两节样板）

### G2-U3-L02《接住掉落水果》（图形化，`scratch-vm`）

- 五要素：今天学循环（重复）与侦测（接住判定）；解决“让篮子接住落下的水果”；学完能用循环移动篮子接住不同位置的水果；联系上节键盘控制小船（方向键改坐标），本节改用脚本控制移动；当前步骤为搭脚本并运行一次。
- 提示：1 级看水果 x 再想篮子往哪边走；2 级运动积木移动、重复块重复下一块；3 级先右移一个大步再用重复块走两小步，具体数字自己算。
- 判定：知识证据 = 循环确实移动了篮子；任务判定 = 篮子真实移动并接住；范围标注 = 教学定向（行为化评测建成前）。
- 注意：原型演示值（水果 x=200、阈值 80）只是演示参数，不是正式教学参数；正式下落步长、水果分值、篮子边界与阈值以三号教学参数方案经首席裁定为准。

### A1-U3-L02《实现文本摘要》（摘要编辑，`summary`）

- 五要素：今天学忠实摘要（只写原文有的要点，不添不改）；解决“从短文里挑出 3 句要点，写出忠实摘要”；学完能判断一句摘要是否忠实（要点齐全、无重复、无离题）；联系前置 A1-U3-L01《建立安全的模型调用》尚未建成（生成式等批），本课用本地规则抽取，不调用外部模型；当前步骤为读课文、选出要点句并核对。
- 提示：1 级先读每段第一句找要点；2 级同一要点只留第一次出现的那句；3 级对照清单（三项要点齐全、无重复、无离题）。
- 判定（五项检查）：要点 A / B / C 齐全、无重复、无离题；五项全过才合格；定位为受控抽取式摘要，不得宣传为通用自然语言摘要理解或生成式 AI 能力。
- 注意：台账 focusConcept=`API` 与“能使用 API”目标为旧规划模板残留，须在样板 B 整改 PR 内一并订正本课一行（只动本课一行），订正前不得宣称通过内容一致性门禁。

## 五、v1.1 扩展字段（已合并实现 OPS-020，PR #469，合并 651ae7f3）

以下字段均为可选扩展，不改变第一节必填字段；缺失时外壳按 v1.0 行为渲染，不得因此拒绝契约：

| 字段 | 说明 |
|---|---|
| `structuredHints` | 结构化三级提示：每项 `{level: 1\|2\|3, title, text}`；揭示为累计式（揭示第 N 级即显示 1..N 级），与 `hints[3]` 同义，不提前展示答案 |
| `methodSteps` / `scopeGap` / `progress` / `activities` | 课程信息扩展，只渲染在任务抽屉内，永不进入永久编辑区；`progress` 为 `{label, current, total}`，`total > 0`；`activities` 每项含 level/title/text |
| `fileCapabilities` | 文件能力 gating：`{canNew, canSave, canExport, canImport, canReset}` 均为布尔；适配器不支持的操作直接隐藏按钮，不得渲染点了只弹提示的空按钮 |
| `hasStage` | `false` 时不渲染任何舞台区（无舞台课程，如摘要课、插槽课）；缺失时按引擎默认 |

扩展字段校验失败时按第三节 fail-closed 处理：外壳拒绝渲染该契约，不猜测补全。

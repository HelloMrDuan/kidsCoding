## 2. 产品级冻结候选（仅桌面方案，需用户批准）

- 顶部课程栏：课程名、关卡进度、保存、文件操作与帮助，保持稳定。
- 顶部单行/双行紧凑任务带：关卡标题 + **当前可执行的一句话** + 下一步动作；完整教案留在提示抽屉。任务带不可完全隐藏。
- 左侧：至少约 26% 宽的清晰作品舞台（随窗口响应），舞台旁或下方角色和背景列表；真实运行/停止按钮固定可见。仅有单角色运行能力时不可伪装支持多角色独立脚本编辑。
- 中间：可见的积木分类及当前分类的可用积木；进入新课时默认展开有用的分类。**分类本身与可拖积木首屏均可见**，不能仅放在 420px 画布下方。
- 右侧：面积最大的 **真实 Blockly 工作区**；积木初始位置应靠近阅读起点，而非孤立在画布中间，拖放需显示吸附/撤销反馈。
- 底部：默认一行儿童能懂的反馈。完整三层判定和工程日志通过折叠“详情”展开；数据层判定不得被删除。
- 示例视觉比例：舞台/角色约 28%，积木分类+素材约 19%，脚本区约 53%，仅供首轮评审，最终须根据真实浏览器实测确定。

**教学忠实性**：第一关仅有“开始时”是合法教学设计，不能为了填满屏幕直接放入“移动”积木；问题在于分类、提示、运行入口和操作流程不明显，而不是第一关积木数少。

## 4. 视觉验收不等于引擎验收

原型中的积木、角色移动和反馈是纯交互示例，不是产品功能。正式实现必须同时过：
1. **视觉**：同尺寸浏览器下与用户批准的截图/原型一致，首屏角色、分类、可拖积木、真实脚本、任务和运行可见；无冗长技术文案遮挡；没有新增套壳导航。
2. **行为**：真实 Blockly 拖拽吸附、修改、执行、判断、重置、保存、恢复。只用按钮模拟加积木不通过。
3. **教学**：第 1 关“仅开始时”不走、第 2 关 100 步、第 3 关先预测再 200 步、第 4 关错误实验观察与纠错，1→4 全程不刷新。
4. **健壮性**：云失败、导航失败、本机存储失败、跨关状态隔离、奖励幂等等现有用例无回归。
5. **多端**：桌面 1440×900 与 1366×768；平板 768×1024；手机 375×812，分别提供同一状态与交互场景的截图。窄屏可以重排，但不可把主要功能藏在不可操作的底部。
6. **真人验收**：首轮仅做一节真实课堂；邀请未经开发指导的实际使用者完成“找到运动积木→接到脚本→运行→判断角色是否移动”，记录卡点。不能以自动化截图代替。

## 8. 2026-11-18 对首次实现 `a1894bc9` 的视觉退回裁定（不可用 CI 替代）

**结论：产品视觉 FAIL；本轮不应进入合并。** 该结论根据用户提供的 1440×900 实拍及真实分支源码检查作出，不代表相关功能单测失效。

### 核心缺口与必须修复的结构

1. **缺少常驻素材面板**：`lesson-workspace.tsx` 仍在 `>=1280px` 下使用 `280px / 120px / 56px / 其余全部` 的四列网格，分类栏仅 56px，真实可拖积木必须点击分类后等待 flyout 弹出。**原型要求同时可见分类和可用积木**。应将角色整合入舞台区域（可放舞台下方），形成大约 **28% 舞台和角色 / 19% 分类+素材 / 53% 脚本** 的三大面板。参考起始宽度：1440 视口内舞台+角色约 390–420px、素材约 250–290px、脚本占剩余，不强制每像素相等，但不允许只留 56px 分类栏。
2. **真实积木素材必须是 SVG Blockly flyout 或真实 Blockly 能力的实际呈现**：不可使用原型手绘 SVG 做产品积木；正式面板需默认显示当前关最有用的分类和可拖积木，分类切换后仍处于素材栏，不侵占编辑画布的主要视野；桌面不滚动即可见。
3. **第一关教学例外须忠于 `launch-lessons.ts`**：`lesson-01-forest-hello` step-1 的 `allowedBlocks=['when_start']`，第二关才开放 `move_right`。原型同时展示“运动”分类是**视觉占位，并非正式教学允许操作**，正式第一关应以“事件—开始时”为默认素材；第二关展示“运动—向右走 100 步”。不得为让截图更丰满而提前解锁运动积木。
4. **任务和反馈还需产品级样式**：原型顶端有清晰关卡进度、主行动按钮、紧凑任务说明；当前实现是缺乏统一按钮/卡片样式的普通文字。首屏不能以大段开发术语替代下一步行动。反馈详细三层结果可展开，但展开后必须约束滚动高度，不让整页因日志膨胀。
5. **角色与舞台**：真实角色数据已接入是进步，但 120px 狭窄角色专栏挤压舞台；角色卡片可进入舞台区域下方，同时保障主要舞台实际宽度与角色运动可观察性。
6. **原型与代码视觉基准缺位**：现有 `studio-forest-hello-v3.spec.ts` 仅断言 `ws-icon-rail` 可见、`lesson-block-palette`（画布**下方按钮区**）在视口、第二关点击 flyout 后看到运动积木；不验证**固定素材面板**，也不验证各区域宽度、真正的首屏教材路径。因此即使 5/5 PASS，产品视觉仍 FAIL。

### 改正后的硬门禁

- 桌面 1440×900 与 1366×768 的真实页面必须显示**舞台 + 角色 / 常驻分类和积木素材 / 可编辑脚本**三大区域；实际积木可从素材区拖至脚本区并真实吸附。
- 将首次实施分支的截图与参考原型**同一视口并排**放进 PR 证据，提供各区域边界框尺寸与偏差原因。未达比例可在必要时说明真实引擎约束，但不能由作者单方面以“信息架构等价”直接判 PASS。
- E2E 新增断言：可拖素材块位于一个独立、首屏可见的面板；不是 `lesson-block-palette` 下方文本按钮，也不是仅在 click 后挤占主编辑区的无常驻 flyout；第一关默认至少显示真实 `when_start`，第二关显示真实 `move_right`；拖拽后主工作区快照和执行结果可观测变化。
- 正式运行/停止/保存/提示/完成按钮及状态必须有明确的儿童产品样式和可见性。
- 修复前不创建声称 V3 已完成的 PR；已存在技术实现分支可继续基于现有功能补布局，保留引擎、判定和全部回归。

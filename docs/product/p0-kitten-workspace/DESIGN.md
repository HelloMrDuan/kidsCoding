# P0 Kitten 式统一工作区设计

版本：`p0-kitten-workspace-v1.1`
裁定：2026-11-02 duan——设计方向批准；v2 演示原型有条件认可，尚未通过完整交互验收；全量迁移继续禁止。
地位：本目录为 2、3、4 号并行开发的同一套规范。改设计须经首席裁定；用户确认前不批量改造 432 节。

## 一、定位

KidsCoding 首先是儿童能自主创作的编程平台，其次才是展示教学说明的课堂页面。图形化课堂以编程猫 Kitten / Kitten N 编辑器体验为主参考，但正式课堂继续保留 KidsCoding 自身品牌规范。本次冻结的是信息架构和交互原则，不是 v2 原型每个像素、颜色与按钮位置。

## 二、冻结的信息架构

- 左侧：作品舞台。
- 舞台旁：角色管理（角色与背景共用一列，背景在最下方）。
- 中间：积木分类与素材面板。
- 右侧：大面积真实脚本工作区，优先保证真实积木编辑空间。
- 顶部：课程名称、当前关卡、作品保存状态。
- 舞台附近：运行 / 停止单按钮（同一位置切换，不并列两个按钮，不随页面滚动消失，不每区块重复）。
- 辅助区：任务引导、三级提示、反馈、课程进度收进任务抽屉与反馈区，不长期占用一个完整大栏。
- 统一反馈区与文件菜单（新建 / 保存 / 导出 / 导入 / 恢复初始）。

孩子在同一视野内完成：选积木 → 拖动拼接 → 改参数 → 运行 → 观察 → 调试。

## 三、三端布局与交互（真实宽度验证，不得仅缩小浏览器画面冒充）

### 桌面 1440

舞台列 + 角色列 + 积木分类列 + 脚本工作区同屏；舞台与脚本同时可见；舞台缩放只改列宽，不销毁引擎、不重置脚本、不丢草稿。指针拖放（鼠标与触摸通用）、改参、重排、拖到垃圾桶删除。

### 平板 768

不强迫三栏。舞台行置顶（舞台 + 角色横排，设显示 / 隐藏开关）+ 下方积木分类与脚本工作区两栏；触摸拖放、改参、删除须真实可用。

### 手机 375

舞台 / 积木 / 脚本 / 任务四工作区切换的专门触摸模式；切换只切换可见面板，不重建引擎、不重置脚本、不丢草稿。手机端不得只验证“切换标签不丢脚本”，必须真实可用：

- 素材抽屉位于脚本工作区内：点积木插入脚本末尾，不用跨标签拖放。
- 脚本内 ↑ ↓ 排序、✕ 删除、数字输入改参。
- 运行按钮在脚本工作区内可达，不依赖切回舞台标签运行；摘要检查按钮同理在摘要编辑区内可达。

## 四、课程引导：目标栏 + 任务抽屉

孩子进入课堂必须立即知道：今天学什么、要解决什么问题、学完能做什么、和上节课有什么联系、当前要完成哪一步。完整教案不直接堆放在主工作区；任务抽屉按需展开，默认收起。每节含探索预测、独立解决、迁移创作三层；三级提示逐步揭示，不提前展示答案；完整参考实现只在事后节点出现。

## 五、统一工具栏与角色管理

- 运行作品（主要）与停止（次要语义，同一按钮切换）固定在舞台头；作品操作（保存作品、导出、恢复初始）收进顶栏文件菜单；调试信息进可展开高级面板；任务抽屉入口在顶栏。
- 角色管理：当前角色高亮、点选切换归属；角色增删与造型编辑在真实引擎接入时落地，原型只演示选择与归属，不冒充已实现。
- 儿童文案：运行作品、停止、保存作品、重新开始；技术术语只进开发者信息区。

## 六、品牌规范

沿用 V2 已冻结规范：深蓝外壳、科技蓝主操作、中性浅色内容区；内容区卡通、可爱、彩色、圆润。工作区新增 token 由首席在原型评审后冻结，任何账号不得单方面改 token、布局尺寸与按钮体系。

## 七、Kitten 实机参考证据摘要（公开页免登录观察，2026-11-02）

Kitten N 编辑器（V1.7.1）公开页实测：左→右为舞台约 26%、角色列约 7%、分类图标条约 3%、展开的积木面板约 11%、脚本工作区约 52%；顶栏文件菜单 + 保存 / 发布按钮；运行 / 停止为舞台正下方居中单按钮切换；角色与背景共用舞台右侧窄列；12 分类图标条 + 点击展开双语面板 + 底部搜索框；竖版 / 横版两种舞台方向入口。未验证项（明确记下，不冒充已对标）：登录墙内功能、窄视口自适应、拖拽手感、控制台触发方式。图标条与搜索框为 2 号实施时的细化项，v2 原型以文字分类标签演示结构。

## 八、停止条件（用户确认新设计前）

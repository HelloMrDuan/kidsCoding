# P0 共享 LessonWorkspace 文件所有权与协作边界

版本：p0-kitten-workspace-v1.2（2026-11-11，文件归属说明更新，接口和 V2 视觉不变）

**本文件只管共享工作区的文件责任，不是 432 节全项目课程归属表。** 全项目归属统一按 [四账号课程归属](../../roadmap/AGENT-OWNERSHIP.md)，执行规则按 [AGENTS.md](../../../AGENTS.md)。

## 一、文件责任

| 工作范围 | 负责人 | 边界 |
| --- | --- | --- |
| 共享 LessonWorkspace 外壳、响应式三域、任务/素材抽屉、工具栏、反馈区、编辑器插槽、运行适配器、共享工作区 E2E | **2 号 Muse**（按主 Muse 授权的产品 Task-ID） | 共享组件不带课节答案，不堆叠课程 ID 判断；接口变更须先获授权 |
| G2 Scratch 自身的课程数据、教学参数、VM 接线、课内判定与适配层 | **3 号 Muse** | 只改明确领取的课程资产，不复制共享外壳 |
| A1 等自身路线的课程数据、内容契约、草稿、活动与判定 | **4 号 Muse** | 复用共享外壳，不能跨课程乱改 |
| 设计/参数裁定、共享文件冲突、目录台账、workflow 串行合并、V2 视觉冻结 | **主 Muse** | 仍需唯一 Task-ID、真实 CI 和非作者审核 |

## 二、强制边界

1. 课程特定模块只归该课负责人；改共享接口或 V2 token 必须先走主 Muse 的独立产品任务裁定。
2. 一个共享核心权威实现，不给各课复制一份；课程作者只实现课内适配器、插槽和测试。
3. 共享 CI、台账、目录同文件冲突按主 Muse 统一串行，后合并者基于新 main 合并，不得覆盖先合并的其他任务。
4. 2/3 号课默认由 4 号非作者复核 + 主 Muse 集成；4 号课由主 Muse 第一复核；主号自己写的代码由其他实际非作者审核。
5. 共同 GitHub 身份的 COMMENTED/PASS 不能冒充 GitHub APPROVED；工程审查不能代替人工教研、儿童试学或最终发布。
6. 已合并课程的原始作者、真实 PR 和工程证据不可因换账号而追溯改写。
7. 本文以当前文件责任为准，历史样板 PR 和旧基底不构成今天的派工指令。

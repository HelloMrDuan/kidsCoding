## 9. 扩展建议（不破坏现有 ID / 进度 / 作品）

只提方案，不在本 PR 改结构；全局扩展架构由 Muse 负责，以下为 Hark A 路线的需求输入。

1. **单元可变课时**：S0、R0 需要在 U1 前增加“安全前置”内容；建议允许单元插入 `L00` 或按 `lessonOrder` 排序而非依赖 ID 序号，既有 ID 不变。
2. **新增单元而非改写**：S0-U5「密码与受控安全实验」（凯撒密码、频率分析、哈希、平台靶场谜题）；R0 增加“模拟器入门”单元；移动应用以 W 路线新单元（PWA）试点后再评估独立路线。
3. **年龄分层字段**：在课程元数据增加 `ageBands`（如 7–9 / 10–12 / 13+）与对应目标，解决 M0/S0/R0/D0 跨度过大问题。
4. **引擎能力按课声明**：G1 及之后路线的 `requiredCapabilities` 必须按课细化，并与 `engine-capabilities.ts` 对照自动检查。
5. **跨路线重复登记**：同题材允许存在，但需在元数据写 `relatedLessons` 与“本课新增能力”，由 CI 检查是否声明差异。

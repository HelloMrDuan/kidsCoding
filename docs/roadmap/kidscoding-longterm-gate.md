# KidsCoding 长期门禁（新增文件，不改现有规范）

> 本文件是新增的长期门禁清单，不修改、不替代仓库已有规范。
> 已有规范仍以原文件为准：`AGENTS.md`、`docs/design/kidscoding-v2/VISUAL-LOCK.md`、
> `docs/design/kidscoding-v2/prototype.html`、`docs/design/kidscoding-v2/DESIGN-SPEC.md`、
> `docs/roadmap/08-CURRICULUM-QUALITY-AND-432-ROADMAP.md`、
> `docs/roadmap/09-TEACHING-QUALITY-GATE.md`、`docs/roadmap/10-TEACHING-QUALITY-EXEMPLARS.md`、
> `docs/roadmap/11-TASK-EXECUTION-POLICY.md`。
> 与已有规范冲突时，以已有规范和项目负责人已裁定的内容为准，先报告差异并等待裁定，不得先改后报。

## 1. 适用范围

本门禁适用于 KidsCoding 全部课程和页面，包括 Python、C++、AI 等专业课程。
未满足本门禁的课程和页面，一律不得宣称正式完成或发布。

## 2. V2 视觉统一门禁

- 全站唯一已批准视觉基线是 KidsCoding V2。所有页面必须与首页保持同一品牌视觉：
  导航、颜色、字体、按钮、卡片、插画、反馈及移动端规则统一。
- 冻结外壳与变量见 `VISUAL-LOCK.md` 和 `DESIGN-SPEC.md` 第 4 节：
  222px 左导航、76px 顶栏、页面底色 `#f3f6fb`、卡片 `#ffffff`、线条 `#e7edf5`、
  导航 `#152238` / `#1c2c46`、文字 `#18243a`、次级 `#6f7d92`、品牌动作 `#2463eb`、
  成功 `#148767`、警告 `#ad6b20`、错误 `#d64c4c`、按钮圆角 8px、主要卡片圆角 14px。
- 专业工作区可以有不同的工具布局，例如 Blockly、Scratch、Python 实验室在
  `DESIGN-SPEC.md` 第 3 节中的工作区划分，但不得私自定义另一套品牌风格，
  不得另起一套配色、字体、导航、按钮或反馈样式。
- 儿童内容区必须卡通、可爱、彩色、圆润，必须使用真实插画角色和原创插画。
  严禁使用纯色圆形、文字色块代替真正的卡通角色和原创插画。
- 已记录的 V2 AA 缺口不得隐藏，也不得擅自改色。任何布局或颜色变更，
  必须先获得项目负责人明确批准，再单独走设计变更 PR。

## 3. UI 验收门禁

- 所有 UI 改动必须提供真实 Chrome 三端截图及功能验证：
  1440x900、768x1024、375x812，正例、反例与恢复测试，PR CI 与 main CI 证据。
- 原型截图、演示数据、模拟运行不是验收证据。不得擅自变更已冻结的 V2 设计。

## 4. 课程教学质量门禁

- 每节课必须具备完整教学过程，不能只写知识点和代码片段：
  情境、预测、引导、至少两种目标不同的亲手练习、真实错误与调试、
  创意改造、可保存重开的作品、复盘与反馈。
- 适用 `08` 单课资产合同、`09` 单课 100 分门禁与硬否决、`10` 样板。
  90 分及以上只是优质课程候选，不是正式发布；80-89 分必须整改；80 分以下退回重做。
- AI 自评、字段填全、自动检查通过，都不能单独证明质量达标。
  独立人工教研、真实运行器证据是独立门禁；儿童试学需真实儿童与监护人同意，不得模拟或伪造。

## 5. 八大专项审定门禁（新增为常设门禁）

此前八大专项只出现在 Hark A 一次性审定 `docs/curriculum-audit/hark-a/HARK-A-144-AUDIT.md`
第 8 节（AUD-101），未写进 `08` / `09` / `10` 的常设审定门禁。本文件将其补为常设要求，
不改动该审定报告本身。

以后每次课程审定必须覆盖全部八项，每项记录覆盖判定、缺口、优先级、所需引擎、
真实可运行的综合项目目标与验收方法：

1. 跨语言衔接：Blockly → Scratch → Python → C++
2. 数据库与数据应用
3. 软件工程与测试
4. 游戏开发
5. AI 应用
6. 网络与安全
7. 移动应用
8. 机器人与硬件

AUD-101 已记录的主要缺口，仍作为未解决项，不得因本文件而视为已解决：
SQL 与数据建模缺失；移动应用缺少完整链路；机器人与硬件缺少模拟器；
AI 缺少运行器；网络安全缺少 HTTP、哈希与受控实验环境。

## 6. 432 基线与兼容门禁（新增为常设规则）

- 432 节、18 条路线是 V1 规划基线，不是系统上限。
- 新增路线和课程必须保持旧 ID、学习数据、作品兼容：
  不改写已有课程 ID，不破坏已有学习进度与作品映射；
  新增内容优先以新增单元方式加入，例如 AUD-101 第 9 节建议的 S0-U5 式新单元，
  以及单元内 `L00` 或 `lessonOrder` 排序方式；同时补齐年龄分层、按课引擎能力、
  重复题材的差异声明。
- 协调说明：在仓库现行校验 `scripts/check-task-ledger.py` 仍要求恰好 432 节、
  且课程台账与目录完全一致的情况下，新增目录课不能在单课 PR 里悄悄破坏该校验。
  改变目录规模、校验规则或进度与作品映射，必须另起统筹 PR 并与其他账号协调，
  在该统筹 PR 落地前，不得把目录外的课宣称为系统目录课。

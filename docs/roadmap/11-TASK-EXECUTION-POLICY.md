# 11｜强制执行规则：每次只交付一个任务，完成即更新 GitHub 状态
> 制度建立：2026-10-11。**所有后续工作都必须按本文件执行，无论用户回复“继续”多少次**。本制度不等于当前软件功能已完成。

## 1. 唯一任务来源与粒度
- 产品/教学/运行器/前台/云端/发布：**[任务总账 task-register.json](./task-register.json)**；每条含任务 ID、名称、优先级、前置依赖、涉及文件/范围、完成条件、状态、PR/合并/main CI/测试证据。
- 全量 432 节课程：**[课程逐课任务总账 lesson-task-register.json](./lesson-task-register.json)**；与现有 full-catalog-v1.json 的 18 路线、72 单元、432 ID 精确一致。每节单独编号、目标、先修、教学质量验收和证据。
- 当前情况：已有九节独立 Blockly 能部分运行，不能因为这九节历史工作就自动给 432 课标完成；另有独立12课不属于432。两套ID的映射由 SYS-101 单独实施。
- 优先级依赖见 [02](./02-PHASED-DELIVERY.md) 与 [07](./07-PR-BY-PR-IMPLEMENTATION-BACKLOG.md)，任务总账字段比段落式计划的泛指更适合更新状态。

## 2. 一轮只做一件事：单任务交付
1. 开工必须写明唯一 **Task-ID**（例如 `EDU-101`、`UX-001`、`G0-U1-L01`）。查依赖并领取 `todo` 任务；若过大必须**先拆成单个可验收的子任务**，不得打包三四个未完成的目标。
2. 写清楚孩子本轮新增能做什么（或页面/运维真实解决什么）、目标文件、至少一条成功/失败/恢复或适用的证据。课程须符合[09教学质量门禁](./09-TEACHING-QUALITY-GATE.md)，页面须符合[07页面门禁](./07-PR-BY-PR-IMPLEMENTATION-BACKLOG.md)。
3. 在**同一功能 PR**修改实际代码/测试和总账里此任务的 `status`，记录 PR 编号/测试与剩余缺口；禁止同一 PR 宣称完成多个独立任务。只有受当前任务直接影响的文档/依赖修复可并入。
4. 真实检查 **CI 全绿 + 无合并阻塞**后合并 main；看合并后 main CI。CI 不绿就继续修 **同一任务**，不换下一个，也不把状态改完成。
5. **完成后必须回填任务总账及 [TASK-CHANGELOG.md](./TASK-CHANGELOG.md)**，记录时间、具体 Task-ID、成果、变更文件、PR URL、合并 SHA、main CI URL、正反测试与仍未完成项。必要时用**单独的记录 PR**在主分支 CI 通过后回写；这属于同一任务的收尾，不算领取第二任务。
6. 只有真实证据齐全才能标 `completed`；否则 `in_review`、`merged_waiting_ci` 或 `blocked`，并记阻塞/恢复计划，禁止假报。完成后才从下一项未完成任务继续。

## 3. 状态转换（必须如实填写）
| 状态 | 意义 | 什么时候允许改 |
| --- | --- | --- |
| `todo` | 尚未开始，不等于不存在早期原型 | 发现任务并登记 |
| `in_progress` | 已进入真正实现 | 任务认领，开始修改业务 |
| `in_review` | 功能和对应测试已推 PR，正在等待CI/审核 | 记录 PR；**不可宣布完成** |
| `merged_waiting_ci` | PR已合并，但main CI或人工验收未完成 | 合并SHA记录到总账 |
| `completed` | PR合并、main CI成功且完成标准验收 | PR URL、合并SHA、main CI、测试证据均完整，适用时人工复核 |
| `blocked` | 当前受真实技术/权限/环境阻塞 | 必填原因、解锁条件、下一次重试/替代方案 |
- 不使用单纯「测试数通过」「写了教案」「PR提交」当作全部完成。生产部署、儿童试学、付费商业课程对标必须有独立证据。

## 4. 一次任务完成的最小交付包
- 唯一任务编号、实际要解决的问题、影响课程/页面/数据范围；
- 目标/实现代码、所需资源、运行器和实际可用界面（或该任务本来就是专项文档/运维）；
- 成功、失败/边界、重试/恢复测试；必要的真 Blockly/VM/Pyodide Chrome、PostgreSQL RLS；
- PR号/最新 SHA、合并SHA、GitHub Actions **PR** 和 **main** CI；
- 截图三断点（UI任务）、儿童课程教研评分（课程任务）、授权来源与人审/隐私（适用时）；
- `task-register.json` 或 `lesson-task-register.json` **状态更新** + `TASK-CHANGELOG.md` **一行可追溯记录**；
- 在答复中只汇报当前 Task-ID 的「已交付 / 尚未完成 / 阻塞 / 下一个」，不把周边任务混成一批。

## 5. 自动门禁的能力与边界
- GitHub Actions 的 `task-ledger` Job 运行 `scripts/check-task-ledger.py`，检查任务/课程清单唯一编号、432课程与官方目录一致、状态/依赖、完成证据、PR Task-ID。
- 该校验可挡住明显假状态/漏ID/格式错误，**不能代替代码执行、教学评分和生产验收**。完整课程/页面仍按原七项 CI 和独立教研/设计审核。
- 原有历史 PR 不因新制度突然倒填完成；任务的历史账由 OPS-005 分批核对。所有新 PR 从本制度合并后要求 Task-ID，不随意绕过。

## 6. 下次“继续”时的操作流程
1. 读取 main 下此文、02/07 与两套 JSON；按前置、优先级取**一个**未完成 Task-ID。
2. 只做这个任务直到可提交的真实结果，仍不能完成时记录具体阻塞，**不空泛说继续**。
3. 提交 PR/CI/合并，更新状态及日志，报告下一条编号。
4. 严格避免：“同时开十个功能”、“合并了就说发布”、“给所有432节统一改成已完成”、“只做规划不触发实际任务”。

## 7. 每次交付收尾机制（OPS-004 落地）

第 2 节第 5 步的"回填"按本节执行，不凭记忆、不凭习惯。收尾属于原任务的一部分，不是新领的任务。

### 7.1 触发条件
功能 PR 已合并，且合并提交在 main 上的两条工作流（curriculum content checks、mandatory task accountability）全部成功。main CI 未绿之前不得开始关账，先按第 2 节第 4 步在同一 Task-ID 上修复。

### 7.2 收尾五步
1. **取证**：记录功能 PR 的编号与 URL、合并提交完整 SHA、main 两条工作流的 run URL，并逐个打开验证链接可达（写错或 404 的链接不得入账，见 UX-104 教训）。
2. **开关账 PR**：从最新 main 切分支，只改两个文件——台账里本任务的条目与 `TASK-CHANGELOG.md`；PR 描述沿用同一 Task-ID 声明（独立成行、仅一行），标题注明"关账"。
3. **回填台账**：本任务条目 `status` 改 `completed`，`evidence` 补齐 `pr`、`mergeCommit`、`mainCI`（及可用的 `mainTaskCI`/`prCI`/`prTaskCI`）、`reviewer`（谁在何时以何种授权批准）、`tests`（正例、反例/边界、恢复用例的真实结果，注明本地与 CI 的来源区别）。
4. **写交付日志**：`TASK-CHANGELOG.md` 追加本任务执行记录一行：日期、Task-ID、成果内容、PR 链接、合并 SHA、main CI 双链接、状态 `completed`；未完成项与技术缺口如实写入内容列，不留空话。
5. **合并并复核**：关账 PR 的 CI 全绿后合并；再看它在 main 上的 CI，并从主分支原始文件读回该条目，确认 `status=completed` 且证据字段齐全，才算正式关账。读不回或对不上，按未完成处理。

### 7.3 强制校验与审计
- `scripts/check-task-ledger.py` 在每次 PR 与 main 推送时强制：`completed` 条目必须有真实 PR URL、完整合并 SHA、main CI URL、测试证据，且 CHANGELOG 中存在该 Task-ID 的记录行；缺任一项 CI 直接失败，关账不得绕过。
- 任一时点可按同一口径审计全部 `completed` 条目（字段齐全 + 日志行存在）。2026-10-23 OPS-004 认领时审计：42 个已完成产品任务证据链 42/42 完整。历史条目的事实真伪逐项核对属于 OPS-005，不在本机制内。

### 7.4 失败与例外
- 合并后 main CI 变红：该任务回到 `in_progress` 在同一 Task-ID 上修复，不另领新任务，也不保留 `completed`。
- 写入操作被平台中断（审批超时、会话重启）时：先只读核查 PR/分支的真实状态再决定是否重试，禁止把"调用没返回"当成"没执行"或"已执行"。
- 任何一步证据拿不到：状态停在 `merged_waiting_ci` 或 `blocked` 并写明原因与恢复办法，禁止假报关账。

## 1. 全站视觉变量（先做 UX-0）

### 1.1 Tokens（建议实现 `apps/web/src/app/globals.css` 与 `apps/web/src/features/ui/`）

| 类别 | 可编码初稿 | 原因/注意 |
| --- | --- | --- |
| 主色 | `#FF8B47` 暖橙，强调按钮背景；`#2F6BFF` 辅助行动蓝 | 保持当前品牌暖色，不直接套竞品蓝紫 |
| 背景 | `#FFF8EF` 奶油、`#EEF6FF` 天空、`#F6FCF6` 自然绿色 | 区分任务/舞台/作品卡，避免满屏大渐变 |
| 正文 | `#16233F` / `#52647A` | 文字对比通过 WCAG AA；深橙实测可能需加深 |
| 成功 / 警告 / 错误 | `#137C50` / `#A85F00` / `#C63E42` | 状态必须还配图标和文字，不只颜色 |
| 网格 | 4 / 8 / 12 / 16 / 24 / 32 / 40px | 组件间距使用 token，不允许自由散落 |
| 圆角 | pill 999px；按钮 14px；任务卡 20px；故事板 28px | 对应不同视觉层级，不要每层都 2rem |
| 阴影 | 卡片 0 8px 24px rgba(20,39,64,.08)；浮层 0 18px 40px rgba(20,39,64,.14) | 低端设备和性能优化 |
| 最小触控 | 44×44px；主要 CTA 52px 高 | Blockly 工具区与浮层不允许误触 |
| 字体 | 中文系统字体优先；H1 30–40、H2 24–28、H3 20–24、正文 16–18px、辅助不小于 13px | 低龄任务文本以可读优先，数字等宽可选 |
| 动效 | 点击反馈 120–180ms；切页 180–260ms；关卡成功 400–650ms；自然终止 | 动效仅为设计目标，必须遵循 reduced motion |
| 内容最大宽度 | 营销/地图 1280–1440px；课室 1440px 及以上可扩展 | 课堂尽量利用横向空间 |
| 品牌资产 | 狐狸/小熊/蝴蝶 3 个主角，四个世界、12 关卡节点、4 枚单元徽章 | 必须 KidsCoding 原创/授权，风格统一 |
| 音效 | 运行/成功/错误三类；初始可关闭；绝不自动播放长背景音乐 | 有声反馈不能干扰教学与家长 |

### 1.2 组件体系

实现位置优先 `apps/web/src/features/ui/`，在当前代码结构中渐进迁移，不一次性重写：

- `KcButton`：variant primary/secondary/quiet/danger，size sm/md/large，状态 idle/loading/disabled/success，事件真可用。
- `KcLessonCard`：进度 0/part/completed，锁定与预览分离；点击仅进入真实可用的课程。
- `KcStatusTag`：大纲/详案/实验可玩/发布门禁/正式上线，语义与数据直接绑定。
- `KcProgressTrack`：课程步骤、4 单元进度、章节完成率与键盘可访问标签。
- `KcFeedbackPanel`：成功/错误/提醒/保存失败、第三层提示展开、无彩色之外的语义提示。
- `KcStoryDialog`：角色头像+一句任务（单屏不宜长段），有展开细节/跳过且不丢步骤。
- `KcPageHeader`：返回、标题、当前任务、保存反馈/菜单，桌面和移动端有不同布局。
- `KcProjectCard`：真实项目封面/时间/课程来源/存储类型/继续编辑动作。
- `KcModal`：键盘焦点管理、Esc、aria label、遮罩点击可选、不挡 Blockly 运行。
- `KcEmptyState`：空作品/未登录/网络异常/未开放课程的真实说明。

所有组件必须覆盖 hover、focus-visible、active、disabled、loading、error 和触屏按下态；新增组件不得先在全站替换，先走实际页面试点。

## 2. 基础通用壳（每页公用）

- 导航桌面：左侧 Logo/当前位置，右侧课程、作品、学习进度、家长入口/头像；当前路由有 aria-current；不显示未实现的入口。
- 移动底栏：学习/作品/我的三个核心区，进入专注课堂后隐藏无关导航但保留返回；底部安全区适配 `env(safe-area-inset-bottom)`。
- 状态：加载有 skeleton、离线有继续本机选项、失败提供重试、锁定说明原因；不展示假数据图表和虚构家长评价。
- 路由：后退不会丢草稿，正交互按钮不使用 `href="#"`、没有空回调；老课程/历史作品 URL 兼容。
- 适龄：G0/G1 文字短、图像大、触摸强，G2/G3 逐渐增加编辑密度；高年级代码区注重键盘效率。

## 3. 逐页面规格（包含实际仓库文件）

### PAGE-01 官网首页 `/`
现状 `apps/web/src/app/page.tsx` + `features/marketing/story-stage.tsx` 等。

**Desktop 1440×900：** 首屏上方 64–76px 简洁导航，下方约 55/45 主视觉区：左侧一句原创价值主张、两行辅助说明、一个“立即试玩”主 CTA（真实落到可用课）、一个“查看真实作品”次入口；右侧主角+舞台/积木原创建模组合。首屏滚动下一屏是按 6–8、9–12、12+ 的课程路线、真实孩子作品示例（无作品时称官方演示项目）、家长如何了解进度、免费体验入口。不得抄竞品课程照片/代言。
**Mobile 375×812：** 标题→CTA→角色画面→真实项目实例，导航为折叠可触达；首屏无需滚 3 次才能找到试听入口。
**功能：** 点击体验进入真正可执行的关卡；不要展示不可用课程“马上学习”。
**验收：** 页面 LCP/CLS 基线、主 CTA 可达、无虚构宣传数字；E2E 从首页到真实 Blockly 编辑器。

### PAGE-02 年龄分层/能力评估 `/onboarding/age`、`/onboarding/check`
现状 `apps/web/src/app/onboarding/age/page.tsx`、`.../check/page.tsx`。
**视觉：** 全屏大插画 + 三种可触达卡片，不像冗长表单；步骤 1/2 提示、角色解释、跳过/返回。评估题不以羞辱性语言评判。
**功能：** 年龄推荐和能力测试写入真实本机/账号进度，刷新/返回不丢失，无法保存显示提示。
**验收：** 各年龄路线与推荐关卡一致；键盘与读屏标签、375px 正常选课。

### PAGE-03 学习地图 `/learn/map`（最高优先）
现状 `apps/web/src/features/lessons/map-view.tsx`、`app/learn/map/page.tsx`。

**Desktop：** 最大宽 1360，头部 72px；左侧约 300px “今日任务/推荐下一课/上一课成果”，右侧约 950px 有连续冒险地形。设计一条实实在在的曲线路径贯穿四区：
- 森林（第 1–3 关）：狐狸/木屋/树叶，节奏为开始→移动→对白。
- 草地（第 4–6 关）：小路/河流/旅行道具，节奏场景变化→重复→旅程作品。
- 花园（第 7–9 关）：蝴蝶/花田/点击反馈，节奏事件→对白→互动表演。
- 毕业岛（第 10–12 关）：双角色/礼物/终点，节奏角色切换→协作→毕业项目。
每关节点的数字、标题、可用状态、奖励同样来自课程/进度数据。推荐课节点大于普通节点；锁定关卡可查看说明但不能报已完成。
**Mobile：** 单列纵向滚动地图，路径连续不溢出；“继续关卡”吸底；点击节点弹出详情卡，可返回地图原位置。
**交互状态：** not started / available / current / passed / locked / not published，配色、图标、文案三重区分；当前 10–12 课若未通过真运行验收不能误显示已可玩。
**验收：** 顺序解锁、重新学已完成课不多发星、断网回访、部分进度 3/12 与全完成 12/12，以及 375/768/1440 屏。

### PAGE-04 Blockly 课堂 `/learn/lesson/[lessonId]`（最高优先）
现状 `GuidedLessonShell`、`BlocklyWorkspace`、`PlayableStage`。

**Desktop 布局**：最小 1280 宽下建议 28% 任务区 / 35% 舞台区 / 37% 积木区（具体可以随内容 ±5%），顶部 64px 课程名/进度，底部固定 74px 运行/重置/提示/下一步工具条。舞台区域至少 420×300，可实测角色坐标、点击和对白，兼容 16:9；Blockly 工具箱与画布独立滚动/缩放。
**任务区**：每步只呈现目标+可选预测+当前观察；提示按 1/2/3 层展开。运行错误时显示实际观察 vs 预期并可定位关键积木。
**编辑区**：分类颜色和按钮结构清晰，真实可拖拽/删除/连接；改变代码后旧通过结果失效；允许重新运行，兼容旧课草稿。
**Mobile 375**：标题/故事+三 tab“舞台、积木、结果”，切 tab 不卸载 Blockly 实例；运行/重置为吸底主要动作，软键盘/缩放不会覆盖舞台；单手可选触发事件。
**验收**：运行成功、错误积木、空程序、点角色事件、关闭重开恢复、断网、奖励幂等；真实 Blockly E2E，手机触控演练。

### PAGE-05 Scratch 课室 `/learn/scratch-lab/[lessonId]`
现状 `features/scratch-vm/scratch-vm-trial.tsx` 等。
**Desktop**：顶部课程步骤/作品保存状态；左侧任务提示，中央真实舞台，右侧代码/角色素材/属性，底部绿旗与停止。对受限 VM 实验清晰标“课程演示/非完整 Scratch 编辑器”。
**需求**：素材库、角色切换、代码编辑、舞台渲染可用后才升级为完整课室；本机草稿、用户私有云端、导入/导出分别有可靠状态。
**验收**：真正 Scratch VM 运行、重复绿旗/停止/分身清理，坏 SB3 文件和云端 401/503 报错，数据不串号；国产常见网络下资源可加载。

### PAGE-06 Python 课室 `/learn/python-lab/[lessonId]`
现状 `features/python-lab/` 与 Pyodide。
**Desktop**：左栏任务、概念/示例，中间编辑器（至少 50% 有效编辑宽度），右侧“运行结果/测试案例/调试信息” tab；顶部课程名/草稿状态；底部运行/重置/保存。需要保留可操作代码区域的文字对比与字号。
**Mobile**：编辑器/测试结果独立 tab、虚拟键盘不遮盖运行键，代码缩进/复制粘贴可用。
**验收**：真实解释器运行、至少 1 成功 1 错误 1 边界、超时、草稿恢复；正式认证和浏览器练习反馈明确区分。

### PAGE-07 课程总目录与详情 `/learn/catalog` + `/learn/catalog/[lessonId]`

**Desktop**：左侧路线导航/年龄难度筛选、右侧按单元的图文卡、代表作品和先修知识；不密集列满 432 个无法打开的按钮。
**Mobile**：路线横向滚动切换，卡片单列，重点 CTA 只针对可操作实验/正式发布课程。
**数据**：每卡显示 L0 大纲、L1 详案、L2 引擎、L3 可试玩、L4 验收、L5 已发布的真实状态；已有 192 详案与 432 大纲不可误记。
**验收**：所有课程状态和后台一致，URL 深链可用；无假“售完/已发布”标签。

### PAGE-08 作品夹 `/learn/portfolio`、`/project/[projectId]/complete`

**Desktop**：瀑布或等宽 3 列作品卡，真实缩略封面、作品标题、语言/课程、更新时间、来源（本机/账号），主要“继续创作”，次级“预览、导出”，列表有筛选。
**Mobile**：单列作品卡，点击进入项目详情，作品动作无误触。
**空状态**：展示原创引导和可用体验课链接，不冒充已有学生作品。
**验收**：有/无作品、坏草稿、跨设备恢复、不同账号不可见；重复保存不出现虚假版本和成绩。

### PAGE-10 奖励与收藏 `/cards`

现状 `features/parent/`。
**视觉**：清晰专业的浅色信息面板，首屏显示学习的知识点、上次学习、可打开作品、建议，避免夸张儿童风仪表盘。
**验收**：家长只能访问关联儿童授权范围内数据；无已核实结果就不展示“AI 打分”；移动端卡片叠放、原始记录可追溯。

### PAGE-12 运营后台 `/admin`、`/admin/catalog`、`/admin/catalog/[lessonId]`、`/admin/lessons/[lessonId]`
现状管理员只读课程审阅与发布门禁相关页面。
**信息架构**：课程状态筛选/详案审阅/引擎能力/自动评测/原创素材许可/儿童隐私/人工批准/发布/下线/回滚。审核按钮必须与真实 API、授权角色挂钩。
**验收**：普通用户 403/redirect；人工门禁缺一项不允许真正发布；记录历史、变更作者与失败原因。无真实发布动作时只能称“审阅后台”，不能虚假放“已发布成功”。

### PAGE-13 登录/购买 `/auth/bind`、`/parent/purchase`、`/parent/purchase/success`
**要求**：可信、简洁、中文条款，清楚标记购买范围与课程真实交付状况。儿童隐私、监护人同意优先，价格/优惠只能取真实可用数据；支付不成功不显示成功。
**验收**：未登录→完成绑定→回学习页；认证/支付失败可返回重试；不通过虚构购买记录构造 UI。

## 4. 响应式断点和截图场景强制矩阵

| 设备 | 分辨率 | 必测情境 |
| --- | --- | --- |
| 大桌面 | 1440×900 | 地图主视觉；Blockly 三栏；Scratch/Python 功能区 |
| 一般笔电 | 1280×800 | 课堂布局不遮挡运行工具条；舞台可操作 |
| 平板 | 768×1024 | 课堂变两栏或分区；角色点击、Blockly 缩放 |
| 大手机 | 390×844 | 地图单列、吸底 CTA、关卡完成弹窗 |
| 标准手机 | 375×812 | 任务→舞台→编辑器→结果全链路 |
| 极窄手机 | 320×640 | 无横向滚动、按钮可点击、必要布局退化 |

每个 UI PR **至少**提交前后对比 1440、768、375 三尺寸截图。复杂课堂必须真实手机/等价触屏完成运行，而不是只运行 Playwright 桌面端。检查最小点击热区、颜色对比、键盘焦点、屏幕朗读文案、错误态、慢网、减少动效偏好。

## 5. 统一界面状态字典（不可只做 happy path）

- 默认/有数据/空数据/加载/慢网超时/离线/错误/重试/未登录/无权限/锁定/存储冲突/储存成功/运行成功/评测失败/未审核/未发布。
- 保存与同步区别：本机已保存 ≠ 账号已同步；云端返回成功后才显示云端状态；401 不显示任何其他账号数据。
- 奖励状态区别：预测错不等于关卡失败；真实运行过关才可标完成；设计新视觉不得破坏奖励幂等逻辑。
- 低龄用户错误反馈：描述“角色没有移动，因为还没有触发开始事件”，而不是“ERR_INVALID_BLOCK”。

## 6. 每页 PR 的交付定义

1. 页面组件真实落地、业务态实际接通；
2. 新增/更新截图三尺寸和清晰的 Before/After 差距说明；
3. 至少一条成功、失败、返回/恢复 E2E；
4. 组件键盘/触控/无障碍自动和人工检查；
5. 原创素材台账和许可；
6. 关键导航路径支持深链接和刷新；
7. 对标证据 URL 和主观视觉评分，明确没做到的点；
8. 提交 PR、CI 全绿、合并 main，合并后复核。

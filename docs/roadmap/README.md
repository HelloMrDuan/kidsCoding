# KidsCoding 产品总纲与唯一开发入口

> **用途**：今后开发先读本文件，再按阶段计划推进。本文是路线图，不代表所列功能已实现。
>
> 事实盘点基线：2026-10-11 / e745aa3c1b3b58a6626cdf3cb864f603d6d0c221；2026-10-11 的成熟竞品对标扩展基于 854e47c1157536adf1cc5499847526322522e4ef。状态以当前真实 main 及验收为准。

## 一、产品定位

面向中国儿童的原创游戏化编程学习平台。目标不是展示大量课程标题，而是让孩子在年龄合适的任务里**看懂 → 预测 → 编程 → 真实运行 → 发现并改错 → 创造作品 → 保存和复学**。为家长提供可以核验的学习过程，为运营提供逐课发布和权限控制。

技术基础：Next.js / React / TypeScript、Blockly、Scratch VM 实验环境、Pyodide、Vitest、Playwright、Supabase、GitHub Actions。各引擎的能力边界必须清晰，不用假的 Scratch VM 或 Python 解释器冒充真实执行。

## 强制目标：教学内容与页面双对标国内成熟产品

**课程内容和页面体验必须同时达到成熟产品可比较的质量，不能只增加 432 节目录或只改几个背景色。**

- **内容**：按编程猫公开 6E 情境/探究/创造/迁移/评估、核桃编程公开的多次动手和学习报告、西瓜创客公开 PBL/创作螺旋等方法建立自己的教学流程。每课要有新知识、运行、试错、分层提示、自主改造、作品、反思，真实课程不同于静态教案。
- **页面**：学习地图、课堂分屏、角色/舞台、积木编辑、Scratch/Python 工作台、作品、家长、后台与首页都要以国内成熟少儿编程产品的视觉完成度、信息密度、儿童可操作性为标杆。**页面既要吸引孩子，又要能真正完成学习任务。**
- **证据**：每个教学/页面 PR 必须有可核实竞品来源、采用/舍弃理由，视觉改造须有 Before/After、1440×900/768×1024/375×812 三断点截图、实际交互回归及原创素材授权记录。
- **执行文件**：[03 内容和页面对标矩阵](./03-COMPETITOR-CONTENT-UI-BENCHMARK.md)、[04 页面 UI/UX 设计与验收规范](./04-UI-EXPERIENCE-BLUEPRINT.md)，它们是正式开发约束，不是可选参考。

允许参考公开的教学框架、组件布局、交互方式、色彩搭配思路；不能直接搬运对方专有角色、logo、图片/音效、付费课件、题库或源码。

## 二、学习产品信息架构

1. **选课入口**：按年龄/水平推荐，展示学习路径、前置知识、已发布课程；大纲与待开发课只预览，不提供假的「立即运行」。
2. **关卡工作台**：任务目标 → 猜一猜 → 积木/代码编辑 → 真实舞台或解释器 → 失败诊断 → 再运行 → 通过证据。
3. **单元作品**：每单元 6 课服务一个真正能展示和修改的项目；给自由创作留空间，不要求所有学生作品严格相同。
4. **作品与成长**：本机草稿、登录后私有云端作品、版本与课程关联、学习进度；正式成绩必须由可信机制生成。
5. **家长/运营后台**：了解孩子学了什么、成果是否真实可复现；逐课审核内容、素材、引擎、安全和测试后发布。
6. **儿童体验**：原创角色与故事、连续闯关、适当配音和动效；游戏化服务学习，不把收藏馆、排行榜、首页美化放在当前主线前面。

## 四、统一教学方法（借鉴方法，不复制商业课件）

参考国内成熟少儿编程产品的情境驱动、项目式学习和连续练习，以及 Scratch/Code.org 的创作、调试、分享和反思理念。以下为 KidsCoding 自己的教学契约：

1. **任务情境**：孩子理解角色、目标和约束；每课原则上引入 1～2 个新概念。
2. **观察与预测**：写出或选择运行前的预测；预测错不直接扣分。
3. **亲手搭建**：编辑真实积木或源代码，不用预先录制的动画代替执行。
4. **运行与验证**：观测坐标、场景、对白、输出或计算结果，覆盖至少一条失败/边界路径。
5. **分层纠错**：先提示现象，再解释概念，最后给针对性操作提示，而不是直接暴露整题答案。
6. **作品创造**：至少一项可更改参数/行为/角色或独立任务，保留作品与重试证据。
7. **复盘迁移**：说清为什么成功、如果改变条件会怎样，家长/老师可看到可复现的作品。

## 五、从内容到正式发布的状态机

- L0 大纲：名称、概念、目标、前置知识。
- L1 详案：剧情、逐步教学、测试标准、提示、创意拓展齐全。
- L2 引擎实现：真实代码/积木执行，任务与执行器关联。
- L3 集成可试玩：前台完整路径可运行，本机作品能恢复，正常与失败路径可观察。
- L4 验收合格：CI + 真浏览器 + 权限 + 安全 + 授权检查过关，保留证据。
- L5 正式发布：负责人逐课批准、部署验收、运营后台解锁。

**不可跨级**：有详案 ≠ 已运行；引擎演示 ≠ 课程完备；本机评分 ≠ 可信成绩；GitHub CI 通过 ≠ 生产部署验收。

## 七、计划变更规则

- 新需求先对照本路线图，说明解决的真实学习问题、依赖、验收与不做项。
- 执行阶段以 [02 分阶段计划的勾选状态](./02-PHASED-DELIVERY.md) 为准；完成后在**同一 PR**更新状态和真实证据链接。
- 新发现问题先修当前阶段 P0 阻塞，再决定是否扩张课程。未经批准不批量将 432 节变成「已发布」。
- 内容与 UI 双验收：增加课程须有能力递进、真实动手、错误和作品；改页面须有可点击真实控件、三断点截图、原创资源、移动端与无障碍回归。不得只用新的渐变和圆角宣称已经对齐成熟产品。
- 不复制编程猫、核桃编程、西瓜创客等未经授权的商业音视频、IP、课件和题库；原创素材需留来源/许可记录。
- 如果本文件与现有代码冲突，以可验证的 main 代码为事实依据，并提交修订此计划的 PR。

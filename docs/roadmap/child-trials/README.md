# 儿童试学计划（RELEASE-103）

目的：在课程申请正式发布（L5）前，用**经监护人同意、年龄合适**的真实儿童操作一遍完整流程，找出卡点，并留下可追溯、匿名的记录。没有有效试学记录时，任何页面、文档、宣传都不得声称课程“经儿童实测/验证”。

## 1. 首批试点范围
| 批次 | 课程 | 适龄 | 建议人数 | 每次时长 |
|---|---|---|---|---|
| 试点 A | G0-U1-L01～L06（网格寻路，L06 为单元作品） | 5～7 岁 | 3～5 名 | 每次 1～2 课，单次不超过 30 分钟 |
| 试点 B（可选） | 启蒙 lesson-01～12 | 5～9 岁 | 2～3 名 | 同上 |
| 暂不试点 | G3-U1-L02、P0-U1-L01～L06 | 9～13 岁 | — | 引擎/许可未验收（RELEASE-101），先不让儿童试用 |

## 2. 前置条件
1. 监护人阅读并签署 `consent-v1.md`（纸质或电子均可），签署日期必须**早于或等于**试学日期。签署件由负责人线下保管，**不放入仓库**。
2. 默认不录音、不录像、不拍孩子正脸；若监护人另行勾选同意录屏，只录屏幕，不录人。
3. 设备：家用平板或电脑的 Chrome/Edge，网络正常；使用本机游客模式，不创建儿童账号。
4. 现场必须有一名成年观察人（负责人、老师或家长），全程陪同，可随时停止。

## 3. 现场流程（每课约 15～25 分钟）
1. 观察人用一句话介绍：“今天我们帮小狐狸找路，你来拼积木。”不提前讲解答案。
2. 孩子自己读（或点朗读按钮听）说明 → 预测 → 拼积木 → 运行。
3. 观察人只在孩子明确求助或卡住超过 2 分钟时，引导其点“提示”，不直接给答案。
4. 每课结束做点选式反思，观察人记录孩子原话（转述、去掉可识别信息）。
5. 孩子表现疲倦、烦躁或想停时立即结束，不计为失败。

## 4. 记录什么（`observation-sheet-v1.md`）
- 是否独立完成；用时；提示使用次数；卡在哪一关/哪块积木；是否理解失败提示；反思是否答对。
- 界面问题：看不懂的字、点不准的按钮、手机/平板布局问题。
- 孩子主动说的喜欢/不喜欢。

## 5. 录入仓库
1. 复制 `_template.json` 的字段，追加到 `apps/web/src/content/curriculum/child-trials-v1.json` 的 `trials` 数组。
2. 儿童只写匿名编号 `C01`、`C02`…和年龄，**不写姓名、学校、班级、联系方式、照片、录音**；CI 会拒绝含这些字段的记录。
3. 记录须由负责人或独立审阅人（非实现者、非 AI）审阅并填写审阅日期。
4. 一个 PR 只录入一次试学，PR 描述写 `Task-ID: RELEASE-103`（试点期间）。

## 6. 与发布门禁的关系
- `child-trial.ts` 校验每条记录：同意、匿名、适龄、可试玩课程、观察人、人工审阅、时长合理。
- 发布第七道门“人审”要求该课至少有 1 条有效试学记录，否则负责人也不能批准 L5（`release-readiness.ts`）。
- 试学只解除“缺试学”这一项，不替代内容审阅、引擎、E2E、授权、进度、隐私等其他门禁。
- 试学发现的问题另立任务修复，修复后再试学一轮再申请发布。

## 7. RELEASE-103 完成标准
- 至少一轮试点 A 完成，≥3 名适龄儿童的有效记录已入库并通过 CI。
- 问题清单已整理并另立修复任务。
- 在此之前 RELEASE-103 保持 `in_progress`，不标记完成。

## 三、随机性：怎样让测试不“看运气”

自己搭的关卡每次运行都真的不一样，所以测试只断言与运气无关的结论：

1. **知识证据只由真实 `operator_random` 收到的上下界决定**。10 次取值全都碰巧落在 ±180 内的概率：上下界 ±300 为 0.6%，±240 为 5.7%，±200 为 35.0%，±190 为 58.3%，±181 为 94.6%（单测里用公式核对）。所以“上下界过宽但这次碰巧都在范围内”的程序，舞台结果会通过，知识证据仍不通过——这一点有专门的单测。
2. 上下界在要求范围内且够宽时，“10 次取值落到范围外”不可能发生；“不同位置少于 3 个”的概率约 1e-20，可忽略。
3. 上下界过宽的程序，浏览器用例**不断言舞台结果**，只断言知识证据。
4. 演示关用固定种子 7：真实 VM 取出 `[-293,-263,287,120,13,-57,-20,-156,32,138]`，与独立的 Python 计算和 TypeScript 孪生实现逐个一致；种子只在真实 `operator_random` 执行的瞬间生效，之后恢复 `Math.random`（有专门的用例）。

VM 边界矩阵（22 行 × 每行跑 3 次，结论必须一致）覆盖：恰好等于要求范围、各超出 1（下界 / 上界两侧）、过宽、最大允许输入 ±500、宽度恰好一半 / 少 1（两侧）、写死一个数、上下界写反（Scratch 对调）、写反且过宽，以及右半边 / 正中间两个迁移关的对应边界。另有：不在循环里、重复次数 1 / 9 / 10 / 20、循环里放两块、两条绿旗脚本、散积木不运行、逐帧 trail 是真实放置序列的前缀、两端都包含（5～6 取到过 5 也取到过 6）、停止 / 停止后重跑 / 被新运行取代。

**沙箱拒绝**：29 种越界工程（不属于本课的积木、上下界超出 / 非整数 / 非字面量、重复次数越界、`将 x 设为` 里没放取随机数、多余的取随机数、散积木、影子积木、连接成环、嵌套两层、积木超过 8 块、脚本超过 3 条、角色名 / 起点 / 造型不对、带声音 / 变量……），每一种都断言**因预期的原因被拒绝**（错误信息包含对应原因），而不是被别的检查误挡；被拒绝后一帧都不运行，沙箱仍可继续使用。

## 四、变异检验

把判定、范围、编译、种子、校验、落账里的 20 处逻辑故意改错（知识证据忽略上下界过宽、改成看运气、各个 `<` 与 `<=`、不对调颠倒的上下界、停止也判定、通过不看知识证据、范围端点不含、编译时上下界互换、散积木也编译、随机数不含上端、上界上限不检查、落账不核对指纹、通过后编辑不失效、trail 不过滤非数字……），**20 / 20 被单元测试发现**。

检验中发现 1 个漏网：“上下界相等时直接返回、不消耗随机数发生器”的改动最初没有测试能发现，已补专门用例（它决定固定种子序列会不会错位），再次检验被发现。

## 五、过程中发现并修复的真实问题

这些都是看截图 / 量几何时才发现的，之前的 DOM 属性断言没有覆盖：

1. **舞台之外的位置看不见**：固定种子序列里 3 个位置（-293、-263、287）在整个舞台（±240）之外，原先的小圆点被舞台的 `overflow: hidden` 裁掉，画面上只看到 7 个点，而这一关恰恰要让孩子看到“礼物跑出去了”。改为贴在舞台边缘的红色三角（CSS 画的，不依赖字体），并有测试断言这 3 个标记的几何框落在舞台画面内。
2. **共享壳在手机上把舞台框固定为 120 / 140 / 200px 高并裁切**：L03 舞台原先固定 4:3 的宽度，高度超出就被裁掉下半截（礼物和圆点所在的行）。壳不能改，所以课程舞台用容器查询单位取“框宽”和“框高 × 4/3”里较小者，三个视口 × 三档缩放，整幅舞台、礼物和全部圆点都在壳的舞台框里且比例保持 4:3（单次 `evaluate` 里量完，避免缩放后布局变化造成的误判）。
3. **手机上“取随机数”积木右端的字被 Blockly 缩放按钮盖住，点不到**：积木比 L02 宽很多。课程自己的 CSS 在手机宽度下隐藏缩放按钮（不改共享壳，双指缩放仍可用）。
4. 舞台框里原来还塞着“引擎状态”文字和“本关要求”说明，把舞台往下顶出约 20px。引擎状态改为视觉隐藏（壳的信息条已显示沙箱状态，DOM 里仍保留），“本关要求”改成舞台左上角的一行小标签。

# G1-U1-L01《给狐狸一个开场》教学设计（第一阶段）

来源：apps/web/src/content/curriculum/track-g1-detailed-lessons-v1.json 中 G1-U1-L01，
年龄 6-9 岁，引擎 blockly，故事：狐狸被选作森林主持人，可它总在故事开头沉默。

## 目标（以详细稿为准，不改写）
- 理解并能解释对白。
- 把开场对白设为“欢迎来到森林剧场”，放在开始事件后。
- 用实际运行结果验证：点击开始后狐狸先打招呼再移动。

## 课堂流程（五步，与详细稿 learningSteps 一致）
1. 观察与预测：先说出什么变化能证明成功（先打招呼再移动）。
2. 拆解与设计：画出操作顺序，说明为什么不能直接跳到最后。
3. 编码与搭建：把开场对白设为“欢迎来到森林剧场”，放在开始事件后。
4. 运行与验收：先预测再运行，只看文本或截图不算程序验证。
5. 边界与修复：故意测试只有移动没有对白、以及对白给错人的情形，修正后重跑。

## 练习（本阶段已用执行器验证，非网页课堂）
- 练习 A（拓展）：在正确程序后，再加一段向观众提问的对白，例如“你们准备好了吗？”。
  执行器结果：仍 success，日志同时包含开场对白与提问对白。
- 练习 B（找错与修复）：先跑只有移动的程序，执行器报错“只有移动没有对白时不能算完成”；
  再把对白补回开始事件后，重新跑即 success。找错证据是执行器报错本身，不是截图。

## 三层提示（详细稿 feedback.tieredHints 原文转述）
1. 先辨认需要变化的对象和目标：狐狸被选作主持人却在开头沉默。
2. 把问题缩小到关键动作：把开场对白设为“欢迎来到森林剧场”，放在开始事件后。
3. 按步骤重试：检查对白积木是否接在事件之后，且属于狐狸。

## 本阶段明确不是什么
- 不是网页课堂可玩课程：未接入 /learn/lesson 或任何 lab 页面，未改任何 web 代码。
- 不是独立教研：无人工教研评分，无签字。
- 不是儿童试学：无真实试学，无监护人授权。
- 不得标 completed：台账只能到 in_review（提交待独立审核），且需在 PR 中如实写明上述缺口。
- 移动步数 100 是本执行器的实现选择（与仓库 duo-dialogue 执行器步数一致），
  详细稿只要求“再移动”，不得把 100 说成详细稿规定的值。

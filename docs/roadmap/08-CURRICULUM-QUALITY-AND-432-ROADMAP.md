# 08｜完整课程建设详细质量标准、18 条路线实施顺序与单课模板

> **硬约束：内容向国内成熟课程靠近，页面向国内头部产品靠近，两者必须同时在孩子端兑现。** 本文不是假装已经掌握所有 432 节精品教案，而是规定每条路线的真实课程生产模型、阶段选题和怎样验证教学质量。当前已有 432 目录/192 详案/72 单元项目蓝图/12 独立启蒙，正式发布仍未验收，参阅 [01 基线](./01-REPO-BASELINE.md)。
>
> **独立课程质量审查**：[09 课程100分、逐条硬否决](./09-TEACHING-QUALITY-GATE.md)，[10 可开发课程教学样板](./10-TEACHING-QUALITY-EXEMPLARS.md)。本文件定义教学结构，不允许“字段填全”就称为优质课程。

## 1. 教育产品能力阶梯：定义课程目标，不按“语言名”堆目录

| 年龄/能力级别（建议，不做硬限制） | 课程产出 | 每单元最低验收 |
| --- | --- | --- |
| G0 5–7 低龄 | 顺序/事件/简单循环，角色完成原创微故事 | 6 课有实际 Blockly 互动，至少一个独立短动画或点击项目 |
| G1 7–9 图形化故事 | 多场景、角色切换、对白与简单游戏规则 | 可玩、可演示、可保存的交互故事 |
| G2 8–11 Scratch 基础 | 原生 .sb3 事件、运动、外观、碰撞/变量 | 真 VM 编辑器支持至少 1 个原创游戏成品，可靠导入导出 |
| G3 10–13 Scratch 进阶 | 分身、消息广播、复杂角色行为 | 真 VM 跑多角色项目，含可重置/重复/异常处理 |
| P0 9–12 Python | I/O、类型、判断、循环、函数 | 真 Pyodide 执行多组样例，项目可保存重做 |
| P1 11–14 Python 游戏 | 绘制/运动/交互/简单游戏循环 | 明确浏览器可执行还是离线项目，不用 PyGame 离线脚本冒充网页游戏 |
| P2 12–15 Python 算法 | 列表、查找、排序、递归及边界 | 真解释器与复杂度概念，正反案例，自动反馈可信度清晰 |
| P3 13+ 数据自动化 | CSV 清洗、简单图表、小任务自动化 | 受控示例数据，不采儿童隐私数据，不做无意义“运行成功” |
| C0/C1 11+ C++ | 语法、安全输入、数据结构、算法竞赛 | 先准备可信沙箱/编译器与资源限额，再逐课开放 |
| W0/W1 10+ Web/JS | HTML/CSS 交互、DOM/JS、网页小产品 | 浏览器安全 iframe、输出可见、作品导出 |
| A0/A1 10+ AI | AI 素养、偏差、数据、可解释的简单模型 | 有真案例与错误结果，禁止捏造模型准确率 |
| R0 9+ 机器人 | 传感器/控制逻辑/程序执行 | 模拟器可重复 + 真硬件适配计划分离标识 |
| S0 10+ 网络安全 | 密码/隐私/安全行为，合法实践 | 受控安全实验，避免危险真实攻击行为 |
| M0/D0 7+ 数学与 STEAM | 几何、仿真、可视化创作 | 真程序计算、可验证与现实学科概念关联 |

18 条目录路线是 G0/G1/G2/G3、P0/P1/P2/P3、C0/C1、W0/W1、A0/A1、R0/S0/M0/D0。每条 24 课、每条 4 单元、每单元 6 课。除 8 条已有 24 课详案路线，其他 10 条尚需详案；后续不能为凑数从竞品照搬整套课。

## 2. 每个单元六课的黄金结构（不机械复制同题）

| 课程位置 | 教学作用 | 真练习数建议 | 必须产生的不同成果 |
| --- | --- | ---: | --- |
| L01 引入/观察 | 角色出现、明确任务、先猜 | 2–3 | 首个可见行为和错误复现 |
| L02 掌握/调试 | 学会一个新的核心概念 | 3–4 | 使用该概念解决不同输入/角色问题 |
| L03 组合/迁移 | 将前两个概念合并 | 3–4 | 可反复运行的组合程序 |
| L04 变化/反例 | 修改输入或参数、解释边界 | 3–5 | 两个不同可观察结果 |
| L05 开放挑战 | 允许多条程序路线达到同一目标 | 2–4 | 与同伴方案不必完全一样的作品 |
| L06 项目展示 | 有真实运行、作品保存和讲解 | 2–4 | 可编辑/保存/重放的单元项目 |

成熟产品“一学九练”体现多次动手的重要性，但少儿课程练习强度需分年龄和教学内容设定；不能把 9 次完全一样的点击包装成 9 次有效练习。对 G0 每节先保障不同目标的 2+ 次动手，后续通过学习试点校准；高阶课程随难度增加可加入更多互异案例。

## 3. 单课资产与运行字段合同（JSON 和实际 UI 必须一致）

| 字段 | 格式/必填 | 是否为阻塞 |
| --- | --- | --- |
| `lessonId` / `trackId` / `unitId` | 全局唯一且稳定，保留历史进度映射 | 是 |
| `targetAudience` / `prerequisites` | 年龄/能力/先修目标 | 是 |
| `conceptsNew` / `conceptsReused` | 本节真正新增及复用知识 | 是 |
| `storyIntro` / `characters` / `goal` | 剧情与完成条件，中文适龄 | 是 |
| `prediction` | 至少一个有区分结果的预测问题 | 是 |
| `steps[]` | 每步不同的编辑任务 + 可观察结果 + 下一步条件 | 是 |
| `practiceCases[]` | ≥2 个独立动手目标，非重复点按钮 | 是 |
| `expectedObservableResults` | 位置/对白/输出/变量/场景等客观状态 | 是 |
| `negativeCases[]` | 错误输入/顺序/缺失事件等至少 1 真实失败 | 是 |
| `hints3Levels` | 现象提示/概念解释/操作建议 | 是 |
| `creativeExtension` | 自由角色/参数/故事/数据变化 | 是 |
| `projectArtifact` / `saveFormat` | 原创作品、可重开、可编辑或明示尚未支持 | 是 |
| `assessmentMode` | 客户端练习 / 服务端可信成绩，严格区分 | 是 |
| `engineRequirements` | Blockly/Scratch VM/Pyodide/编译器具体版本与环境 | 是 |
| `resourceProvenance` | 素材/声音/背景/课程证据的版权来源 | 是 |
| `releaseStage` | L0–L5；默认 L0，升状态需 CI/人工证据 | 是 |
| `parentSummary` / `reflection` | 孩子能口述的知识和家长能看到的真实成果 | 是 |

不能只凭填完字段就把 `releaseStage` 变为已发布；字段仅代表教学资产，运行器、Chrome E2E、原创美术和审核尚需逐项完成。

## 4. 前 12 节启蒙课逐课对应可见成果（依当前 main 的独立 ID）

| 序号 | 课程 | 必须新增/确认的行为 | 典型边界 |
| --- | --- | --- | --- |
| 1 | `lesson-01-forest-hello` | 事件帽块启动与角色移动 | 未运行不可通关 |
| 2 | `lesson-02-forest-greeting` | 移动后说话，角色反馈 | 缺关键积木拒绝 |
| 3 | `lesson-03-forest-story` | 开始、动作、对白组合故事 | 顺序不符合目标需解释 |
| 4 | `lesson-04-meadow-scene` | 舞台真实从森林到草地 | 只有文字标题变化不算 |
| 5 | `lesson-05-meadow-order` | 顺序与重复运动，坐标变化 | 没移动就重复不能成功 |
| 6 | `lesson-06-meadow-story` | 旅行剧情、场景、对白 | 再运行恢复初始状态 |
| 7 | `lesson-07-garden-click` | 点击事件未点击不会触发 | 仅启动不能通过 |
| 8 | `lesson-08-garden-dialogue` | 点击后移动并说话 | 点击错/程序不完整需反馈 |
| 9 | `lesson-09-garden-story` | 点击+重复的互动表演 | 不点击不通关，重复点击控制 |
| 10 | `lesson-10-second-friend` | 独立两角色执行、角色切换 | 切换前后作用对象不可混 |
| 11 | `lesson-11-duo-rehearsal` | 两角色动作和第二角色对白 | 错 actor/失效状态不可奖励 |
| 12 | `lesson-12-graduation-show` | 两角色配合取礼物，可修改作品 | 礼物目标、保存/重启、奖励幂等 |

**当前真实状态**：1–9 的基本 Blockly E2E 之前已有，不等于按本新合同全部完成；10–12 的引擎执行尚未合并。今后按每节新合同逐项补充，不得把“已经存在名称”写成完成。

## 5. 路线建课依赖和优先分批

1. 修独立 12 节的第 10–12 课和作品流程；同时 UX-0/UX-1。
2. 建 12 独立 ID 与 G0/G1 概念映射：不简单叠加或重命名以消除 432 目录重复。
3. G0-U1 六节精品教学：逐课知识进阶、真 Blockly、优质场景、作品和三端 UI。
4. G0-U2～U4、G1-U1 按每批 3–6 节，先完成基础角色/事件/判断/循环等引擎能力后再开发对应课程。
5. P0-U1 六节 Pyodide 原型复核，再完成 P0-U2/U3/U4、G2-U1 Scratch；两个运行器可按独立小批次并行。
6. G3 Scratch 进阶的消息广播/克隆以及 P1/P2 Python 游戏/算法逐步扩展。
7. 其余 240 节详案以「能运行」为约束逐批创作：先有实验平台、目标、原创项目，再写详案/评测，不按语言名一次补齐全部。
8. C++/硬件/高级 AI 等需要单独受控沙箱、版权和安全评估，不得先做静态假运行器占位上线。

## 6. 必须有的教学评测证据与自动检查

- 课程教案结构：schema + 单元进度 + 前置概念边无环检查 + 内容重复检测（不能只换角色标题）。
- 运行器：1 成功、1 反例、1 变化参数、1 重试/刷新恢复；自动核验实际执行结果。
- 自由创作：同一客观目标允许至少 2 条语义等价方案（适合场景时）；如本阶段仍严格验证积木顺序，则明确标练习限制，不声称自由创作已完成。
- 文案年龄适配：低龄故事节奏、解释可读性、错误不羞辱、短指令。
- 资源：图片/动画/音效出处、许可证与审阅批准，不混入对标产品的具体受保护作品。
- 学习进度：每节课记录可复现结果和时间、草稿版本，未有可信服务端验证只能记客户端练习。
- 发布：内容审阅、真实运行器、E2E、儿童隐私、版权、运营批准、生产部署全过才从 L4 升到 L5。

## 7. 页面与教学双重独立验收

- 教学品质按 [09](./09-TEACHING-QUALITY-GATE.md)（独立100分+硬否决），提交不同动手、错误反馈、自由改造和真实作品，候选≥90。
- 页面视觉与使用品质按 [07](./07-PR-BY-PR-IMPLEMENTATION-BACKLOG.md)（另一100分+硬否决），候选≥90。**两个分数都过关也不等于正式发布**，还要真实运行器、版权/儿童隐私和生产发布审批。
- 编写课程 PR 时参照 [10](./10-TEACHING-QUALITY-EXEMPLARS.md) 的可操作情境；尚未实现的练习与项目列阻塞。

## 2. 本文件补充的长期要求

### 2.1 专业工作区共享同一品牌

Python、C++、AI 等课程可以有不同的专业工作区工具（例如 Python 实验室、Scratch 工作台），但不能私自定义另一套品牌风格。外壳、导航、颜色、字体、按钮、卡片、反馈样式仍以 V2 为准，工作区内部差异只限于工具本身（编辑器、积木、舞台、测试结果等），不得以“专业需要”为由另立一套导航、配色或组件视觉。

### 2.2 课程审定八大专项

课程审定在适用时必须覆盖以下八大专项，逐项记录适用、不适用及原因，不得静默省略：

1. 跨语言衔接
2. 数据库
3. 软件工程
4. 游戏
5. AI
6. 网络安全
7. 移动应用
8. 机器人硬件

本条是审定维度，不是新增课程内容，也不是把一节课强行塞进八个专项。不适用的专项要写明原因。

### 2.3 432 节是 V1 规划，不是系统上限

432 节是 V1 规划目录，不是系统上限。后续新增路线和课程时：

- 不得重用已发布课程的旧 ID，不得静默重编号；
- 必须保持旧 ID、学习数据、作品的兼容性，新增 ID 与旧 ID 的映射要单独记录；
- 新增路线先做引擎能力、版权、安全、隐私评估，再逐批开发，不得为凑数照搬整套课。

`08` 第 3 节要求 `lessonId` 全局唯一且稳定、保留历史进度映射，本条将其明确为新增路线的兼容性规则。

### 2.4 跨账号协调与共享规范保护

- 现有共享规范不可擅自覆盖。发现仓库规范缺少已批准的长期要求时，提交独立的补充 PR（如本文件），只新增文件、引用现有规范，不编辑现有规范的规则条文。
- 与其他账号协调：开工前先查台账与开放 PR，确认任务归属；已有开放 PR 的任务不得另开重复 PR 覆盖；补充规范与他人工作冲突时，先协调、解决冲突再合并，不得制造并行冲突规范。
- 本文件本身如需修改，同样走独立 PR，不得直接在他人分支上强推覆盖。

## 3. 完成门禁

任何课程和页面未满足第 1 节与第 2 节的适用要求，一律不能宣称正式完成。状态只能停在 `in_review`、`merged_waiting_ci` 或 `blocked`，并写明未满足项、原因与解锁条件。

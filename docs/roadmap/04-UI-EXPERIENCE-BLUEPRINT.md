# KidsCoding 对标国内成熟产品的 UI/UX 页面蓝图与验收标准

> **必须实施的产品标准，而非仅供参考的美术建议。** 设计对齐国内成熟少儿编程产品的**布局、细节、动线与儿童可用性**；交付必须是独立原创、真实可交互的 KidsCoding 页面。
>
> 本文依据目前仓库页面源码静态检查，而非已完成实际浏览器逐像素截图验收。真实截图和竞品可访问性证据在各页面 PR 中补齐。竞品依据与版权边界见 [03 对标报告](./03-COMPETITOR-CONTENT-UI-BENCHMARK.md)。

## 1. 核心设计方向

**KidsCoding 自有设计主题：「冒险学习星球」**。低龄段是温暖、清晰、精致的 2.5D 卡通冒险世界（森林→草地→花园→毕业岛）；高龄 Scratch/Python/C++ 编辑器逐步转向简洁专业的工具型界面。参考成熟国内产品的**完成度、信息层级、任务流和反馈形式**，而不要求每页做成同一张巨大卡片。

视觉关键词：原创卡通角色、连续世界地图、任务明确、适当游戏化、清晰舞台、可编辑积木、可感知结果、家长放心。

不可接受：整页同质白卡片、堆渐变但无世界叙事、无反馈的「运行」按钮、漂亮截图下的假编辑器、首屏堆满 432 个不可玩课程、未审计素材直接复制。

## 2. 统一视觉设计系统（首个 UI PR 先建）

| 项目 | 规范与开发验收 |
| --- | --- |
| 主色系 | 以当前 `apps/web/src/app/globals.css` 的暖橙 `#ff8b47`、奶油 `#fff8ef`、云蓝 `#eef6ff` 为基础；加稳定的成功、提醒、错误、选中语义 token；对比度验收后调整，不照搬竞品调色板 |
| 卡片 | 地图关卡、课程任务、作品卡、学习反馈分别定义 4 类组件；统一内边距、圆角、阴影和状态，而非随手堆 `rounded-* shadow-*` |
| 字体层级 | H1/H2/H3/正文/提示分层；正文适合儿童阅读，常规中文 16–18px 作为设计起点；关键按钮明示文字，不依赖只有图标 |
| 角色/场景 | 独立 KidsCoding 狐狸、蝴蝶、小熊等原创角色的尺寸、表情、动画、光照/线条统一；形象设计独立，记录设计来源与版权 |
| 按钮 | 主要 CTA 只保留一个明确行动；运行/暂停/重试/提示/保存/返回/下一步具有不同功能与状态反馈；禁止「按钮有样子却无动作」 |
| 反馈 | 正确时舞台变化 + 简洁反馈；错误时明确观察差异 + 分层修正；异步时 Loading 和超时；存储失败不会假报成功 |
| 动效 | 页面切换、成功、错误、角色行动 3 类统一节奏；尊重 `prefers-reduced-motion`、音效默认可控，绝不依赖动画结果作为唯一反馈 |
| 无障碍 | 目标 WCAG 2.2 AA：常规文本对比约 4.5:1，交互对比/非文本约 3:1；触控主要操作目标建议≥44×44px，键盘焦点可见 |
| 适配 | 桌面 1440×900、平板 768×1024、手机 375×812 至少三类；320px 不崩溃，375px 无横向溢出；Blockly 工作区触控/缩放需真机核验 |
| 性能 | 优先绘制真实可操作区：静态资源分级加载、低端机不被粒子动效阻塞，页面视觉升级不可破坏学习引擎和可达性 |

## 3. 必做页面优先级矩阵（源代码与实际改造项）

| 优先 | 当前路由/文件 | 目前源码已具备 | 对标后必须补的体验 | 验收门槛 |
| --- | --- | --- | --- | --- |
| P0-A | `/learn/map` / `features/lessons/map-view.tsx` | 4 单元/12 启蒙课地图、当前关卡状态 | 原创连续冒险岛地图：4 区域背景、路径节点、解锁/已过/可玩/敬请期待分级、下一个推荐 CTA、星星/学习进度、移动端不挤压 | 12 节状态对应真实数据；可点击有效关卡；锁定不可误开；桌面/手机截图验收 |
| P0-B | `/learn/lesson/[lessonId]` / `GuidedLessonShell` / `BlocklyWorkspace` / `PlayableStage` | 任务/积木/舞台/运行/反馈/提示 | 借鉴成熟课堂分屏密度：固定课程/步数进度、任务指引、可拖拽积木、宽敞舞台、预测区、运行控制条、提示与正反反馈；儿童操作重点突出 | 真 Blockly 执行；正确/错误/重置/刷新恢复；无舞台或按钮遮挡；移动端能操作 |
| P0-C | `/learn/portfolio` + 本机草稿 | 作品夹与本机/云端试验能力 | 封面缩略图、作品名称/关卡/更新日期、继续编辑/预览/导出、来源本机/云端、明确保存反馈与空状态 | 当前账号仅见自己的作品；重新打开继续改；作品封面是实渲染/授权图，不放假成品 |
| P1-A | `/learn/scratch-lab/[lessonId]` | 真实 VM，受限编辑/导入导出/本机云端草稿 | 工具化积木栏/舞台/角色素材管理/保存与运行反馈，保持 VM 真实；正式前补原生舞台渲染 | 真实 VM 结果、失败提示、三屏适配，不冒称完整 Scratch |
| P1-B | `/learn/python-lab/[lessonId]` | Pyodide 真运行与多组反馈 | 任务说明、结构化代码编辑、运行/测试、输出/错误分栏、样例和调试提示、历史草稿 | 真 Pyodide、代码错误显示、输入输出和保存，移动端键盘不遮住操作 |
| P1-C | `/learn/catalog` 与 `/learn/catalog/[lessonId]` | 18 路线/432 大纲、详案与试验入口 | 年龄/难度筛选、清晰的单元卡/预览、能力先修、真实项目实例、可信课程开放标记 | 目录数量与状态准确，不把大纲展示成可立即闯关 |
| P1-D | `/parent/overview` | 家长学习概览代码 | 「本周学习」「学会的知识」「孩子作品」「需要鼓励的地方」「下一步建议」，可展示真实学习证据 | 不捏造分数/证书；已完成课程和作品可追溯到数据 |
| P1-E | `/admin/catalog` | 管理员内容库和 7 项发布门禁 | 编辑/审阅/引擎/资源/测试/隐私状态一屏可查；预览与发布操作分离；有审核记录与回滚入口 | 无管理员权限不可操作；发布门禁缺项不可发布 |
| P2 | `/` 首屏/营销页 `app/page.tsx`、`features/marketing/*` | 故事区域、成长路径、家长信任、体验 CTA | 国内成熟教育产品的完整「年龄/分级→体验→作品→成长证据→家长安心」流程；原创插画、真实作品截图、适龄价值说明 | 首屏 CTA 进入真实试玩，禁止虚构报名数、机构合作、学员成绩 |

**实施顺序解释**：优先地图 + 课堂，因为这些真实体验最影响孩子继续学习；作品夹紧随其后。首页仍需要成熟商业产品级视觉，但不能先花大量时间搭一个背后不可玩的营销壳。

## 4. 可直接落地的页面结构线框

### A. 桌面学习地图（1440px）

```text
┌ KidsCoding / 继续冒险 / 我的作品 / 家长入口 ── 星星・头像 ┐
│                  你好，小探险家！今天继续第 7 关          │
│  ┌── 今日任务 ───┐   ┌─────── 连续冒险世界地图 ─────┐ │
│  │ 当前学习目标   │   │ 🏕 森林 —— 🌱 草地 —— 🦋花园  │ │
│  │ 上次进度       │   │       —— 🎓 毕业岛           │ │
│  │ [继续上课]     │   │ 节点: 已完成/当前/锁定        │ │
│  └───────────────┘   └──────────────────────────────┘ │
│   单元完成比例 / 最近作品 / 给家长的学习进度摘要         │
└────────────────────────────────────────────────────────┘
```

### B. 桌面 Blockly 课堂（1440px）

```text
┌ 返回地图 / 第X课・第Y步 / 连续进度 ───── [保存] [?] ┐
│ ┌─────────────┐ ┌─────────────────┐ ┌─────────────┐ │
│ │ 原创剧情任务 │ │ 真实舞台/两个角色 │ │ 积木分类+工作区│ │
│ │ 目标与观察   │ │ 角色位置和对白    │ │ 可拖入、连接  │ │
│ │ 猜一猜       │ │ [▶运行] [重置]   │ │ 可回看程序    │ │
│ │ 分层提示     │ │ 运行后真实反馈    │ │              │ │
│ └─────────────┘ └─────────────────┘ └─────────────┘ │
│ [观察差异] [重试/查看提示]      [验证步骤 / 下一步]    │
└────────────────────────────────────────────────────────┘
```

### C. 手机课堂（375px）

```text
┌ 返回 / 本课进度          保存状态 ┐
│ 本步故事 + 任务目标 + [提示]     │
│ [舞台] [积木] [结果] 三标签切换 │
│ 舞台区域真实运行，触控可点击    │
│ 位置/反馈、运行/重置保持可见     │
│      [检查并继续]               │
└───────────────────────────────┘
```

手机不能通过把桌面三栏压缩到 375px 来算适配，应使用分区切换，切换保留 Blockly 工作区与运行状态。

### D. 作品展示

卡片封面（真实作品结果）+ 项目名称 + 课时标签 + 最近编辑 + 本机/云端状态 +「继续编辑」「播放作品」「导出」；空状态引导孩子创建真实作品，不挂假作品缩略图或假排行榜。

## 5. 每页验收 Checklist

- [ ] **功能对齐**：至少两个官方竞品公开页面参考，说明取舍；控件每项都能产生真实动作。
- [ ] **视觉对齐**：记录 KidsCoding Before/After，审视儿童第一眼能否找到任务、舞台和运行按钮；不能依赖「用了渐变+大圆角」来认定精致。
- [ ] **原创素材**：原创/已授权的角色、背景、图标、音乐、声音，资源清单含 URL/来源与许可；禁止搬运竞品商标和角色造型。
- [ ] **多尺寸**：1440×900、768×1024、375×812 浏览器截图并检查至少一款实际安卓设备或等效触控测试。
- [ ] **交互**：正确、错误、空内容、加载、慢网络、未登录、课程锁定、断网及重试至少覆盖相关状态。
- [ ] **儿童可用**：文字可读、主要按钮触控面积、焦点与键盘、无横向溢出、拖拽区足够大、信息不过载。
- [ ] **可信成果**：运行真实积木/VM/解释器；草稿保存不假报成功；没有安全验收就不自动公开作品。
- [ ] **稳定性**：Playwright 测试关键操作；Blockly 缩放、窗口 resize、移动端进入/退出、返回继续不丢失代码。
- [ ] **性能**：场景动效不阻挡输入；资源加载失败有可用占位；低端设备降级仍可做题。
- [ ] **数据口径**：432 大纲、192 详案、9（当前基线）可运行启蒙与 Python/Scratch 实验数量分别陈述，不虚标正式发布。

## 6. 页面交付 PR 分批（与真实教学主线并行）

| 批次 | PR 范围 | 可交付的实际页面效果 | 不可跳过的验收 |
| --- | --- | --- | --- |
| UX-0 | 设计 token、童趣原创角色资源规范、全站组件规范、视觉基线截图 | 一致的按钮、任务卡、状态、排版与交互，不再每页随意拼样式 | 颜色对比、组件测试、双主题/动效降级、来源许可 |
| UX-1 | `/learn/map` + 12 课分区节点 | 连续冒险世界地图、当前关卡重点、真实状态进度、手机地图 | 节点准确、下一关、锁定态、3 断点截图 + E2E |
| UX-2 | `/learn/lesson/[lessonId]` + Blockly/舞台/提示 | 成熟儿童课堂布局、真实动作/反馈、可视化进度与纠错 | 前 9 课回归 + 第 10～12 双角色成果、错误/恢复、手机操作 |
| UX-3 | `/learn/portfolio` | 真实作品卡、预览/继续编辑/云端状态 | 空状态、无伪作品、A/B 用户隔离、保存/恢复 |
| UX-4 | Scratch/Python 工作台 | 分屏专业操作区与真实程序反馈 | 真 VM/Pyodide E2E、慢网络与异常处理 |
| UX-5 | 课程目录 + 家长页 + 审核后台 | 年龄/学习目标/真实进度/发布状态明确 | 锁定/授权/准确学习证据 |
| UX-6 | 官网/选课首屏最终统一 | 原创插画、真实作品演示、可信引导、完整品牌视觉 | 主 CTA 有真实目的地、移动端及性能测试 |

**UX-0/1 可以与 10～12 课功能开发分别立 PR；UX-2 必须衔接双角色真实执行；UX-3 与私有云端验收关联。** 不允许一个 PR 把整站全面重写，也不允许某个 PR 只有精美原型图没有 Next.js 实际落地。

## 7. 成熟产品对标中的版权和真实性硬边界

我们可以借鉴公开可观察的**布局规律、任务流程、交互方式与通用教学方法**，不能原样复制受保护的界面插画、源码、品牌、学员照片、视频、具体商业课件和测试题库。未经授权不得下载并打包竞品图片放进 public 目录；不得把竞品产品宣传的用户数或效果写成 KidsCoding 自己的成绩。需要高相似的功能体验可以由原创组件实现，外观要保持 KidsCoding 独立身份。

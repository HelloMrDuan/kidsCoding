## 二、游戏与学生脚本

- 舞台：水果（学生脚本）、篮子（课程预置：一直重复「将 x 设为 鼠标的 x」，y 固定 -90）、
  舞台（课程预置：得分/时间复位 + 重复直到 时间<1 { 等待 1 秒，时间-1 } 的倒计时）。
- 学生积木（8 种）：绿旗、一直重复、重复执行、随机出生（x=随机(-200..200)，y=170，显示）、下落一步、
  如果〈碰到篮子？〉、将得分增加、隐藏。嵌套上限 3（接力结构 = 一直重复 > 重复执行 > 如果）。
- 参考做法：一直重复 { 随机出生；重复 fallFrames 次 { 下落一步；如果碰到篮子 { 得分+1；隐藏 } }；隐藏 }。
- 结束条件（沙箱按真实 VM 变量收尾）：得分 ≥ 5 → 获胜；时间 < 1 → 时间到。两者都会在舞台状态条与判定中显示结果。
- 篮子移动是玩家操作（指针），不进判定对错：判定核对的是程序规则，不是玩家手速（同 L04 对“检查时机”的处理）。

## 三、四层活动（对应学习步骤）

1. explore 探索理解（观察与预测）：固定演示 = 参考做法，孩子写两个预测（出生几颗 / 下一颗是否同位置），
   运行并亲手移动篮子接水果，运行后对照真实数字（出生数、不同位置数、接住数）。
2. solve 独立解决（编码与搭建）：从空脚本搭出完整游戏。
3. transferFix 迁移创作 A（边界与修复）：预置毛病程序（记分在“如果”外且不隐藏 → 一颗水果被记很多次、
   落地也记分），孩子先运行看账目，再修好并重新验证。这是契约 FAIL-01 的可复现错误路线。
4. transferFast 迁移创作 B：水果速度 10 → 16，重复次数需按新速度重算（fallFrames 33 → 20），其余规则不变。

## 四、判定三层（judge.ts，只看真实 VM 轨迹）

- 舞台：结束原因与最终变量一致（win 时 finalScore ≥ 5 且等于记分事件之和；timeup 时 finalTimeLeft < 1）。
- 任务：逐颗核算——每次记分同帧必须有 true 的“碰到篮子？”检查；每颗（两次出生之间）最多记一次分；
  timeupFrame 之后不得记分（过期加分）；有碰到却没记分 = 漏记分。玩家没接到的水果不算程序错误。
- 知识（随机）：每次出生的 x 必须与同帧 operator_random 求值相等；出生 ≥ 3 次且不同 x ≥ 3 个。
  写死位置、只换一两个位置、出生没用随机都会在这一层失败——这是本课区别于“固定重复”的核心证据。
- 固定“理解情况”说明随每次判定展示（系统看不出是否理解）。

## 五、关键机制与实测依据

- 真实渲染：沙箱加载 scratch-render 并 attachRenderer，sensing_touchingobject 由渲染器判定；
  运行前等造型包围盒达到真实尺寸（L04 spike 结论），超时报错不静默。
- 可见舞台：共享壳的 scratch 挂载点在舞台框外无尺寸，故适配器先在挂载点起 iframe，
  舞台槽位挂载后把同一 iframe 移入舞台框放大（setStageHost）。指针直接落在画布上，
  沙箱按画布比例换算后 postIOData('mouse') 转发给 VM，篮子脚本读到的是真实指针。
- 虚拟时钟：Date.now 虚拟化，每帧 +1000/30ms；倒计时 20 秒 = 600 帧，与帧严格对应（L05 探针结论）；
  包装 sequencer.stepThread 每遍请求重绘，避免等待线程在一帧内死循环。
- 随机可复现：operator_random 走宿主 Math.random（打包源码实测 low + floor(random*(high+1-low))）。
  沙箱每次运行把 Math.random 换成 mulberry32(固定种子)：随机仍由真实积木求值，同一程序轨迹可复现，
  一局内位置互不相同。种子写在 params.ts 并在证据中披露；判定核对的是“值来自随机求值且互不相同”，不是某个固定序列。
- 几何（沿用 L04 实测）：篮子中心 y=-90（占 -110..-70），水果半径 20，落地中心 -160，
  落地时水果顶边 -140 低于篮子底边 -110，地面上“碰到篮子？”恒为假，不会把落地误判成接住；
  水果从 170 以速度 10 下落，与篮子重叠的窗口约 8 帧，每步都检查不会错过。
